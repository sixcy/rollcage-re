# Renderer vertex-buffer ownership and transfers

`src/renderer-vertex-buffers.mjs` reconstructs the complete reached game algorithms for ownership constructor `52b6c0`, physical GPU allocation/declaration propagation `52c860`, pool lock `52c7c0`, and view lock/unlock `52ca80/52cb20`. It calls the actual recovered logical layout, CPU physical pool, shared-view attachment, declaration cache, pointer-vector growth and debugger singleton algorithms. Retained native-simulation evidence: 13033/13034, 13289–13310, 13331–13350; immutable base/derived vertex vtables are retained in the layout constants. Redux SHA-256 is `c0582271862ec373f00d01545c2a95aef0abb10a32513ec585271d08b10c6cf5`.

The constructor appends the new view to manager `+584` before choosing its physical pool. Mode zero scans manager `+590` for sufficient signed free bytes, mode zero, exact full DWORD flags and matching physical stride. Other modes create a new pool. Pool ownership is appended before its backing allocation and hardware creation, and the constructor continues after GPU creation failure. The returned view is reloaded from its original mutable local where native does so; allocator mutations can redirect that local. Incoming flags are captured only after the first ownership append. Null `operator new` paths can subsequently dereference null in the original; the connected proof declares successful object/vector allocations instead of inventing a recovery policy.

Device method `68h` receives byte capacity, usage, FVF zero, pool kind and the output device-buffer word. Any nonzero HRESULT is failure, including positive HRESULTs. Usage defaults to 8; mode bit two adds `200h`, bit one removes 8 and selects pool kind 2. A successful allocation invokes actual `52c3e0`, stores its declaration, then reloads the global manager and updates matching live views' cached GPU handle/declaration from the captured list bounds.

Pool locks operate in physical vertex units and retry a failed Direct3D lock with `DISCARD` cleared, rereading stride, device pointer and raw arguments. Borrowed view locks temporarily replace/rebase their CPU pointer and restore it on unlock or lock failure. Ordinary uploads use a single memcpy when strides match; otherwise they copy each logical row into the larger physical row. In particular, native mask `20h` adds 16 bytes to the physical pool/declaration but contributes nothing to the logical layout. The extra bytes remain untouched. Mode/update arguments are tested by their low byte. The view's upload counter tests the signed usage WORD at `+a`, not the layout flags WORD at `+1c`; its tenth unflagged update calls the real debugger singleton getter.

The native comparison `tools/verify-renderer-vertex-buffers-instructions.mjs` passes 600 fixture worlds, **9,000 entry calls, 1,193 reached instructions and 1,627,558 steps**. It compares all mapped bytes at and above `10000h`, defined returns, CRT/COM requests and restored FS exception linkage. Cases include shared pools, failed hardware creation, failed/retried locks, borrowed storage, separate row uploads, lazy debugger construction, callback mutations of constructor arguments/local ownership, global-manager replacement, and four persistent constructor/lock/caller-write/unlock frames. The caller's byte writes are declared identical in both worlds. No game callee is mocked; Direct3D/CRT/critical-section operations are explicit services. Six focused tests cover the key recovered rules.

This proof does not execute the original program, driver, window or threads. Renderer startup `510080`, materials/shaders, window setup, teardown and GPU reset/destruction remain separate reconstruction work. Existing CPU-pool/layout/declaration notes describe their broader numeric boundaries and allocation assertions.
