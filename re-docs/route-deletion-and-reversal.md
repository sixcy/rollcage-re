# Route deletion and reversed track drafts

The editor's v6 delivery adds stable route point deletion and an explicit reversed variant. These are offline editor transformations over the recovered native format. They do not reconstruct the original authoring tools or certify that every track can be raced backwards.

## Route point deletion

`src/race-route-topology.mjs` retains the byte-identical v1 no-edit path. An operation upgrades the draft to topology v2, adding `deletedPoints` and a `reversed` marker. Original groups keep their native identities, group 0 remains reserved, and a usable edited group must retain at least two points. A deleted ID remains a tombstone referring to a surviving point; chained deletions are resolved before compilation.

The removal preview selects the next surviving point in the stored native travel direction. At the end of a noncyclic route it uses the previous point. Incoming explicit connections move to the chosen replacement. Outgoing branches transfer to free slots on the preceding point where possible; the dialog exposes occupied-slot conflicts and requires a different owner/slot or an explicit branch removal. Ordinary traversal closes its gap automatically. The preview may be cancelled without changing the project, and the entire operation is one undo step.

Native route links contain a 5-bit group and a 9-bit point in each 14-bit slot. The compiler remaps every packed link, spatial fallback source reference, shared fallback alias and following scenery model word. Source anchors used as immutable clone templates remain valid even when their original visible point is deleted. The relevant native consumers are `48da10` (route fallback) and `429360` (spatial/model references); route direction is the preserved group header byte at offset 2, and cyclic traversal is byte 4. These facts predate this editor feature; the automatic retargeting choice is editor policy.

Generated spline routes use stable `${roadId}-route` groups and immutable authored templates for flags/speeds. Reshaping preserves the common prefix of point IDs and retargets removed tail references. Deleting a road retires its generated group into a zero-count tombstone so subsequent native group IDs do not shift. Retired groups still consume the native 32-group capacity. Generated spatial sectors are associated with their own generated route by `src/generated-route-fallback.mjs`, rather than inheriting an unrelated original group.

Validation: `node tools/validate-route-deletion.mjs NEW_REPORT.json` checks all 40 installed LOW/HIGH resources, rebuilt references and retained model words; the retained matrix is `analysis/route-deletion-matrix-20261025-v2.json`. It also runs 90 JavaScript ticks with three cars on each of the 36 ordinary resources. LEV16/17 have no authored AI routes. Unit tests cover original and added deletion, immutable anchors, tombstones, conflict handling, packed references and road-route retirement. These are source/synthetic validations, not native runtime claims.

## Reversal

`src/track-reversal.mjs` keeps the physical finish as logical checkpoint 0, reverses the rest of the checkpoint cycle, and negates representable checkpoint plane normals. It toggles route travel direction and transposes explicit branch links. A reversed point can have more than the native two outgoing slots: overflow connections remain in the saved report until explicitly connected elsewhere or discarded. They are never silently truncated.

The grid is reflected across the finish plane, then projected onto nearby supported terrain while preserving the original height clearance. Unsupported or overlapping positions block strict Test changes/export. Unrepresentable signed-16-bit candidates are retained in report metadata while the editable draft keeps its last valid vector; the report remains blocked until repaired. The first checkpoint direction determines native initial car heading (`41dbb0`, `41e3f0`), rather than a per-grid yaw.

The viewer supplies `reverseSpeedPadArtwork` to rotate recognized source and saved arrow patterns by a half turn. Unrecognized artwork and scripted scenery receive warnings. Copied AI speeds, jumps/drops, grid clearance and special race behavior require manual review. LEV16/17 remain experimental race candidates. LEV12/13 produce analysis-only blockers and no automatic changes, in accordance with the protected native `44a1c0` sector/stage policy.

The saved report carries structured severity, code and focus targets, pending branch connections, and a complete `originalDraft`. The viewer can download the report, restore the original, and save/reload both states in a v6 project. Strict export recomputes geometric readiness from the actual compiled resources. Warnings do not imply a full race has been validated.

`analysis/track-reversal-matrix-20261025-v2.json` covers all 20 paired source levels. LEV2/4/6/8/9/10/11/14/15/18/19/20 have no structural blockers under the source policy. LEV1/5/7 retain branch fanout conflicts, LEV3 has unsupported grid placement, LEV16/17 require grid repair, and LEV12/13 remain unchanged. Clean cases were compiled LOW/HIGH and ran 90 JavaScript ticks. The v2 matrix runs the full central editor compiler, including recognized original-arrow artwork rotation and preview handling of blocked grid candidates. It is a source result.

Their purpose is initialization evidence: route headers, checkpoint cycle/normals, real car constructor positions, and bounded first-tick headings. `check-native-reversed-track-policy.mjs` validates the frozen wrapper/helper contract without starting a process. Only a completed native capture and `check-native-reversed-track-validation.mjs` can establish original-process observations. A complete backwards race and natural recovery are separate coverage requirements.

## Choose any competing branch (delivery19)

The native slots are now treated as provisional storage rather than fixed user choices. `reversalJunctionBranches` derives every occupied-slot connection plus every waiting connection at a junction, using the existing topology/report format. Focus frames them together as A/B/C, with no default selection. Radio choices and clickable world labels select a branch; the selection is amber and every other candidate is cyan. The junction selector groups overflow records by source point.

`resolveReversalJunctionBranch` supports removing or moving any candidate. A waiting selection uses the existing resolver. A stored selection is cleared or relocated to a different point's empty slot, then one waiting connection takes the freed junction slot. All other connections remain. With four or more candidates, further overflow stays unresolved. Invalid/stale selections, occupied relocation slots and missing endpoints reject atomically. The central paired compiler still runs before changing the visible draft. This changes no project schema and retains the original-draft snapshot.

Synthetic regressions cover removal of either occupied slot, relocation, preservation of all other destinations, multiple overflow records, JSON round trips and atomic rejection. `analysis/reversal-branch-choice-browser-20261025-v2/report.json` covers actual HIGH/LEV1 A/B/C focus, removing stored A, clicking/moving stored B through immutable preview, removing waiting C, saved native connections/report/original snapshot, reload and Camera cleanup. Final focused checks are in `analysis/editor-branch-choice-regression-20261025-v1/report.json`. No native game was launched for this delivery.
