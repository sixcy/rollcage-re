# Material construction and shader-name registration

`src/renderer-material-construction.mjs` reconstructs full `50da10`, including all native kind branches, named/default/empty materials, raw wide-string ownership and actual shader-name registration. Evidence: retained `11248/11249` constructor, `13394/13395` attribute helper, `13396/13397` manager adapter, `13418/13419` name-ID registration, original switch table `13438`, default names `13439`, original manager vtable `11419` and the raw wide-string/vector evidence documented in [renderer-shader-names.md](renderer-shader-names.md). All evidence uses Redux SHA-256 `c0582271862ec373f00d01545c2a95aef0abb10a32513ec585271d08b10c6cf5`.

`constructRendererMaterial(material,enabled,kind,name,runtime)` accepts raw addresses and `{memory,scratchBase,services.libraryCall}`. `scratchBase` is the actual native entry ESP; the parent frame is entry minus 56 bytes. Initial string construction runs at frame minus 12, the explicit attribute call at minus 20, temporary-to-member assignment and manager adapter at minus 16. The initializer maps the independently retained switch/name/vtable bytes for standalone runtimes.

The constructor clears only the native header fields, stores the low enabled byte and constructs its owned wide string. It initializes eight attribute records with type `-1`, a separately read live global index word and tag `030f`, then clears the property-vector header. Kinds 0 and 2 append through actual `50dd70`; kinds 1 and 3 use the native inline stores. Their absent-name defaults are `Stock/Particles`, `Stock/Untransformed Triangles` and `Stock/Pretransformed Triangles`, respectively. Other kinds do not append an attribute or select a default name. Bytes beyond the initialized object fields remain untouched.

The incoming name pointer is captured before initial string allocation, whereas kind is reread afterward. Allocation-side changes to the caller kind/global index therefore affect dispatch/attributes without changing the captured name or enabled byte. The selected name is copied through an owned temporary, then resolved by the live manager's actual `+a8` adapter into the case-insensitive name-ID cache. IDs are stored as a word and registration as byte `+5`. Repeated names retain the original one-based ID while material strings remain independently owned. This registers a name; `5252d0/525f70` program generation/compilation is a separate algorithm.

`node tools/verify-renderer-material-construction-instructions.mjs` passes **1,200 fixture worlds, 3,600 entry calls, 907 reached instructions and 2,055,091 steps**. Each world executes an actual cache constructor and two actual material constructors against shared persistent memory. The proof covers every original kind, named/default/empty/aliased inputs, repeated cache hits and allocation-side changes to kind/name/enabled/global index. All mapped bytes at and above `10000h`, meaningful returns, ordered genuine CRT calls with core child ESPs and restored FS linkage match. The shared cache prefix retains the independently documented narrower CRT-frame contract from the shader-name comparison. No game call is mocked, and no original process is run. Four focused tests cover stock names, unbound fields, ownership/cache identity and live allocation mutations; related shader-name and typed-value tests also pass.

Full material copying/property-vector ownership and shader-source generation/compilation remain open renderer-startup work. This new API is not yet substituted into every older narrow device-constructor path.
