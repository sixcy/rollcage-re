# Vehicle autonomous initialization

`src/vehicle-autonomous-init.mjs` reconstructs the complete `410060` parent and both previously missing numeric descendants, `420270` and `491ee0`. Its public entry is `initializeVehicleAutonomousState(recordPointer, {memory, scratchBase})`: the native ECX argument is a participant record whose first DWORD points to the vehicle body. `scratchBase` is the parent's entry ESP. All state uses the same caller-supplied memory; there is no copied body/session representation and no game callback in this source graph.

The parent captures the initialization guard `6e650d` before clearing the body's `6c0..707` state with the original vector-store widths. On first initialization it captures the session pointer, copies session `+618` into the separate AI/contact random stream `5ea4d4`, and produces difficulty `5ea4d8`: session byte `58c == 1` or byte `551` in `{2,4,6,7}` forces two, otherwise the unsigned byte at `585` is used. It calls actual `buildAutonomousObstaclePolygons` (`4123a0`) before reading session byte `579` to produce mode `920f84`: `0..2 -> 0`, `3..5 -> 1`, `6..9 -> 2`, `10..255 -> 3`. Ownership assignment and route flag initialization then run before the guard becomes one. Subsequent participants preserve this shared setup and continue the already advanced random stream.

If route count `[*90b98c + 46]` exceeds one, the parent reloads `*record` for the two route-state writes: `record+54` points to a group whose byte5 supplies body `+6c0`, and `record+58` supplies body `+6c2`. The remaining reset, profile and planner calls retain the body pointer captured on entry. This distinction is exercised by an actual obstacle-producer alias: its registry `+8` publication changes the participant's body pointer before the route assignment, while policy continues on the original body.

It sets body `+6c4` to `40h`, clears the remaining explicit state fields, copies the low identifier byte into `+6d9`, copies ownership from `91f6a8[unsigned identifier]` into `+6f3`, calls actual `initializeVehicleContactProfile` (`41ebb0`), then tail-calls actual `updateAutonomousProfilePlan` (`41f900`) with mode argument one. The planner receives the original parent entry ESP. The `420270` entry ESP is parent ESP minus12; the original obstacle call is reached at parent ESP minus16, while the profile and route calls are reached at parent ESP minus12. The pure obstacle/reference helpers do not fabricate unconsumed private stack saves.

## Ownership and route producers

`initializeAutonomousCompetitorOwners({memory, scratchBase})` is complete `420270`. It initializes the six owner bytes at `91f6a8..91f6ad` to255, captures session participant count, and classifies participants in their original order. Type8 participants with profile other than6 enter one local byte list; other types enter the second list. Exactly one or two participants in the latter list, and at least one eligible type8 participant, enable assignment. One RNG transition chooses the first type8 participant; when another is available, a forward overlapping byte move removes the first selection and a second RNG transition chooses a distinct participant. With one owner both chosen cars receive that same owner; with two owners they receive the respective identifiers. The two native scratch arrays and their overlapping DWORD local writes remain byte-backed at their real offsets. The native function's compiler-cookie check is a platform/compiler service, not a game algorithm.

`initializeAutonomousRouteFlags({memory})` is complete `491ee0`. Session kind3 or8 returns immediately. For each group after the primary group, an unsigned point count at most20 and flag byte4 exactly one clears that flag. The runtime group stride is12. Each iteration reloads the route-table pointer and group count, preserving aliases rather than snapshotting the groups.

Evidence is retained in `2344`/`2345` for the parent, `2450`/`2451` for ownership, `2452`/`2453` for route flags, and `2454` for the original parent difficulty dispatch bytes. Existing `world-obstacle-registry.mjs`, `vehicle-contact-profile.mjs` and `autonomous-profile-plan.mjs` supply the actual reached game descendants and their original static tables. This package adds no synthesized game tables.
