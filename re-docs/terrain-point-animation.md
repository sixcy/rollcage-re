# Authored terrain-point animation and effects

`terrain-point-animation.mjs` implements actual `44a5c0` construction and full `44a7a0` update. Feature byte `+fc` in pack `90b990` is also the constructor's authored cell count; pack `+100` points to four-byte cell references. The constructor allocates `6000` bytes, resolves each cell's four terrain corner pointers, deduplicates by pointer in first-seen order, and captures original XYZ shorts into24-byte records. Globals `90b994`/`90b998` publish storage/count. Each record receives zero phase plus three RNG draws for phase offset, rate mode and amplitude. If nonempty,32 palette entries are derived from the first vertex's material alpha. Cell count and pack identity are captured before allocation; the actual cell pointer is read afterward. The wider level loader remains a separate scope.

`44a7a0` increments signed16 phases, resets exceeded stored phase thresholds, and still uses that incoming exceeded phase to compute the current sine displacement. Rate modes1/2/3 select3/4/6; all others select2. X/Z share a table displacement; Y uses a one-bit-larger displacement. Vertex writes retain target/base/table alias ordering and update brightness while preserving the low six material bits. Dirty ranges append up to64 entries, suppressing only immediate duplicate values.

Two separately gated RNG paths emit special21-frame debris and32-frame type8 particles through actual pool allocation and spatial lookup/linking. Emission gates still advance the seed with an empty table. Debris reuse and particle lifetime/return-to-free-list are real consumers; no spawn, query or collision answers are supplied by game mocks. Numeric private locals and the compiler cookie word are published at their native producers. Original allocator failures with nonempty authored cells have no safe null-address continuation; that invalid memory domain is not repaired or claimed as a successful constructor scenario.
