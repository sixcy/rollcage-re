Flags, count, texture count, attribute offsets, usage and ownership keep their original16-bit field stores. The allocation guard uses the full signed count, while allocation size uses the live low-word count and live DWORD stride. Positive count65536 therefore still requests zero bytes; negative count retains low-word65535 but skips allocation. Absent attributes preserve stale offsets. Previous storage is freed only when the ownership word is nonzero. The incoming storage argument is reloaded afterward, so a free service can change the borrowed storage decision; high ownership-word bytes remain untouched. A supplied pointer becomes borrowed storage. Otherwise positive full count invokes actual zeroed allocation, with the original native child entry and known caller registers; nonpositive count stores null.
