# Shared-memory respawn placement query

`src/raw-respawn-query.mjs` connects the complete `47d040` placement parent and `47d710` obstruction check to the recovered geometry and pool algorithms. The existing structured `respawn-query.mjs` remains compatible.

The entry is `queryRawRespawnPlacement(body, positionAddress, quaternionAddress, rotationAddress, mode, outputAddress, runtime)`. Runtime supplies `{memory, views, grid, scratchBase, roundingMode}` and any existing model-effect runtime/services required by reached object classes. `scratchBase` denotes native `47d040` entry ESP. The position and quaternion are Q16 DWORD vectors; rotation is nine Q12 signed shorts. A zero quaternion address selects the native null branch. The returned integer is the acceptance result; the output DWORD receives the nearest terrain reference, or minus one for an outside lookup.

Declare the fixed clone as `{address:0x70f130,length:0x3e78}` in the coherent runtime's extra body storage, without inserting it into the physical group. The source obtains that same identity through `views.bodyAt`. Temporary candidates reside directly at `70ed30`; `91e788`, the ordinary candidate arena base, is not replaced. The coherent view's existing model-pointer mapping supplies decoded geometry identities when raw model queries run. The appender itself reads relocated model/object/shape/list storage directly and does not need a separate `models` or `modelPointersFor` runtime option. Grid regions must retain their relocated six-byte table indices, and grid vertices must use the live raw terrain mapping. These are explicit address/asset mappings, not geometry-result callbacks.

The parent converts a nonnull quaternion into the source matrix before copying. It performs the actual forward DWORD copy, `3e78h` bytes for type3 and `180h` otherwise, and preserves copy cursors `70eb00/70eb04`. It reproduces the original captured/free/active shape-pool cursor behavior and forward 72-byte shape copies. Shape-cache preparation writes the shared matrix, float-cache and transform globals at the reached points. The cloned aggregate then receives the supplied position, zero travel and optional mode2 radius8000. Actual raw spatial lookup selects regions; actual uncapped `47d9c0` selection writes retained candidate slots and metric scratch at `70eb30`.

`raw-respawn-model-candidates.mjs` implements `429360` sequencing and `429600` in the respawn parent's exact zero-travel/time-zero domain. It uses the aggregate pose even if terrain candidates have overwritten clone fields, reads live object classes/yaw/position/configurations, transforms/restores the aggregate's four native lanes, publishes per-object counts and writes candidate fields in original order. It invokes the actual plane, point and edge algorithms; the latter two have zero motion and native then forces their acceptance flags to two. This named respawn appender rejects nonzero aggregate travel; it is not a claim of an unrestricted moving-query `429360` adapter.

Empty regions expose consumed private storage. Their otherwise uninitialized nearest ID occupies parent ESP minus136. Actual `429ab0` previously saves its current shape-record pointer at that address; a narrow optional `nativeState.beforeShapeCacheEntry` hook publishes that save at the reached entry point. With zero individual shapes, the previous model appender's count can survive there instead. The raw appender writes its local counter at the original per-object and accepted-shape points, allowing repeated empty-region queries to consume that history. Neither value is synthesized at the end of the placement call.

`queryRawRespawnObstruction(originalBody, mode, runtime)` exposes the `47d710` child when its clone/pools already exist. Nonzero modes test the aggregate; mode zero traverses count-minus-one individual shapes. Its actual terrain and placed-model queries share the original local output address and preserve stale fields. It retains the physical screening's logical displacement shifts and asymmetric `x*x + (y+z)*z` comparison. Original/excluded bodies are skipped by native identity/type. The parent releases temporary IDs in native descending order while retaining shape bytes and pool order. Invalid signed-count workflows are bounded explicitly; no synthetic acceptance result replaces geometry.

## Uncapped candidate behavior

The ordinary terrain APIs keep their default64 workflow limit. A narrow optional `maxCandidates` argument in `terrain-query.mjs`, `terrain-sphere-query.mjs` and `raw-terrain-query.mjs` allows the respawn caller's native unsigned-short domain explicitly. It changes the validation contract, not candidate arithmetic or the ordinary builder's cap. Respawn selection has no native64 cap: candidate64 starts at the fixed clone address. Three full native fixtures admit72 candidates and compare every resulting clone overlap, geometry/global write and allocator release. The reference does not silently truncate or move these stores elsewhere.

A larger artificial144-candidate region was inspected during development: candidate writes overwrite the clone's candidate pointer and signed shape count before geometry runs. That produces a pointer outside the declared parsed terrain storage and is not a supported well-formed geometry fixture. It is neither clamped into a valid result nor claimed as original-process behavior. Runtime body, candidate, terrain and model pointers must refer to the caller's declared coherent address space.

## Validation and limits

`node tools/verify-raw-respawn-query-instructions.mjs` passes192 fixtures and282 complete parent calls, including persistent four-query histories, zero through four shapes, zero-row regions, type3 full copies, short copies of types4/7/12/17/21/22/33, modes0/1/2/3, two-body screening, outside positions, nonidentity quaternion conversion, live model metadata changes and the72-candidate alias cases. It compares **all mapped bytes at or above10000h after every call**, including source/clone bytes, allocator arrays and counters, stale temporary shape records, candidates, planes, border diagnostics and shared arithmetic globals. The private stack is excluded while consumed private values still have to produce matching mapped outputs. No game call is mocked; checked compiler-cookie equality is the sole external service.

The report `analysis/raw-respawn-query-instruction-check.json` records73 accepted calls,6,169,439 interpreted steps and3,831 reached addresses. Reached children include470 region appends,212 model appends,1,050 model acceptance calls,4,596 plane calls,359 point calls,529 edge calls,286 terrain queries and135 placed-model queries. These fixtures exercise ordinary model geometry; separately recovered class1/2/4 effects remain available through the actual raw model query but are not claimed as newly covered class-effect scenarios by this check.

`node --test tests/raw-respawn-query.test.mjs tests/respawn-query.test.mjs tests/terrain-query.test.mjs tests/terrain-sphere-query.test.mjs` passes27 tests, including eight new tests for real rejection, pool cleanup with stale records, source rotation/full vehicle copying, uncapped clone overlap, live model classes, both consumed private values and preserved ordinary API bounds. The existing raw terrain comparison also passes1,800 fixtures plus48 aliases and1,008,160 ordered stores after the optional guard extension. Source evidence is the original `100`, `107` and `108` retained assemblies plus the recovered cache/spatial/model/terrain descendants loaded from the retained exact-target program, including scene `184`/`187` for model append/acceptance. Native child stack addresses are derived from the parent: obstruction entry is parent ESP minus44, its output is child ESP minus40, model query entry is obstruction ESP minus84, model append entry is parent ESP minus44, and region append entry is parent ESP minus56.

These comparisons use synthetic, explicit relocated runtime/asset inputs and retained-instruction interpretation. They do not establish the complete original resource/session loader, every model-effect lifecycle context, original-process execution, or the full outer post-frame/race tick. The parent integration must supply the real memory and mappings and preserve the same rotation identity across fallback attempts. Installed files remained read-only.
