## Practical boundaries

- Roads are upright open strips with height, width and banking; full start/end boundary snaps are supported. Loops, inversion, tunnels, T-junctions and Blender imports are deferred. Generated route speeds are copied reference values and require tuning; endpoint connections are explicit.
- LEV12 sectors2/3/4/5/7/8/10/16 and zero-based stages4/11, and LEV13 sectors0/4/5/24 and stages6–13 are protected in both UI and compiler. Local source/destination edits and generated terrain cannot touch protected areas. Checkpoint order/topology remains locked level-wide; reversal is analysis-only. Spatial tests use a conservative128-unit clearance around protected cell bounds.
- Twelve tracks have structurally clean automatic reversals: LEV2/4/6/8/9/10/11/14/15/18/19/20. LEV1/5/7 retain branch overflow; LEV3 needs grid repair. LEV16/17 need grid/route verification and their AI Racing test remains disabled. Warnings still require manual gameplay review on clean tracks.
- Native imports retain exact texture pixels/palettes and reserved runtime headroom. Transparency-range conflicts, unsupported effects, foreign scripted/destructible ownership and native table/candidate capacities reject explicitly. Generated-route tombstones preserve identities and still consume group capacity.
- Captures launch isolated original executable copies under declared startup instrumentation and bounded read observers. Each positive report confirms171 original files unchanged, with owned game-process cleanup. No native physics/query answer or selected recovery pose was supplied by these observers.

## Reproduction

`node tools/check-editor.mjs NEW_DIRECTORY` runs the focused editor group, without a game launch. `node tools/validate-editor-v6.mjs NEW_REPORT.json` performs the combined corpus check using retained read-only source fixture choices. The slice notes link their independent validators and native policy checkers. Native launches require a separately announced desktop window.
