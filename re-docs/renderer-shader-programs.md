# Shader-program construction and effect metadata

`src/renderer-shader-programs.mjs` reconstructs actual `525720` construction, `5258b0` technique/parameter initialization and `50f130` renderer debugger category. It uses actual owned shader-input resize/assignment and raw wide-name construction. Evidence: retained `13450/13451`, `13402/13403`, `13091/13092`, and original parameter-name/literal bytes `13500`–`13502`, bound to Redux SHA-256 `c0582271862ec373f00d01545c2a95aef0abb10a32513ec585271d08b10c6cf5`.

`constructRendererShaderProgram(program,effect,inputs,name,runtime)` accepts raw addresses and `{memory,scratchBase,services}`. It constructs an independently owned wide source name and vector of 44-byte input records before resolving effect metadata. The effect pointer remains caller-owned; input opaque words are copied as native. The constructor uses entry ESP minus 32 as its frame and enters metadata at frame minus 8.

`initializeRendererShaderEffect(program,effect,runtime)` clears exactly the 24-stock-handle block and technique field. A null effect returns without resetting the unrelated activity byte or input-vector header. Otherwise it forwards the live renderer's state-manager pointer, repeatedly asks the effect for its next valid technique, obtains technique descriptions and validates until a successful technique or exhaustion. Descriptor/validation calls retain the original effect argument while later calls reload the live effect field. Debugger category registration and the printf-looking getter calls execute the actual game algorithms; those getters do not produce formatted log text.

The chosen technique is bound, then all 24 original stock parameter names are looked up and filtered by `IsParameterUsed`. Byte `+4` reflects eight particular retained handles. Custom records receive their handles through their live narrow names, with the pre-call row root used for the write and the live vector count used for continuation. Genuine effect COM methods use `services.direct3DCall(object,method,[object,...args],runtime)` with their actual child entry ESP. CRT allocation, copies and frees use `services.libraryCall`.

`node tools/verify-renderer-shader-programs-instructions.mjs` passes **600 worlds, 3,000 entry calls, 932 reached instructions and 2,283,078 steps**. The comparison checks all mapped bytes at and above `10000h`, meaningful returns, ordered CRT/effect COM requests with child ESPs and restored FS linkage. Each constructor world continues through three metadata refreshes. Cases cover null effects, failed enumeration, zero handles, first/second valid and all-rejected techniques, 24 stock and populated custom parameters, lazy category registration against a declared initialized debugger, and COM-side effect-root/input-end changes. No game call is mocked and no original process is run. Three focused tests cover technique selection, exact null-effect writes and owned constructor-to-custom-parameter flow.

This proves metadata and owned program construction with an existing effect COM object. `525f70` source-path generation/D3DX compilation, the larger reload/font graph and renderer bootstrap remain separate open work. Fresh debugger singleton construction is independently recovered elsewhere; this check explicitly starts with that singleton initialized.
