The lock's x86 Win32 object occupies bytes `manager+854..86b` (24 bytes). The following `+86c` depth and `+870` owner are eight bytes of **game wrapper state**. Retained `4a7a0b INC [EDI+18]` and `4a7a0e MOV [EDI+1c],EAX` produce those values after GetCurrentThreadId returns. `4a7a40` decrements depth and `4a7a45` clears owner only at zero, before Leave. They must execute through the real game port and must never be copied from a post-service snapshot as an OS result.

The original V18 input has Win32 DebugInfo `ffffffff`, LockCount −2, RecursionCount 1, owner TID 37368, semaphore zero and spin 4096; the game wrapper separately has depth 1 / owner 37368. The actual worker already owns this lock. This supports a recursive acquisition interpretation; it does not decode LockCount's private implementation bits into a waiter count. Microsoft's [EnterCriticalSection contract](https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-entercriticalsection) permits repeated entry by the owning thread and defines no return value. [LeaveCriticalSection](https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-leavecriticalsection) also has no defined return value; [GetCurrentThreadId](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getcurrentthreadid) returns the calling thread's ID. No void EAX zero or cached main-thread result is justified.

A future typed observer needs a **new explicit extension** to the open owned-worker gain window. The existing policy fixes three activation IDs and two endpoint snapshots; appending ordinary generic breakpoints would not provide the required worker/source/caller lifetime proof. The extension should preserve the original owned CREATE_THREAD/TID, bound gain source/manager/G, actual caller/force, activation guard, normal RET8 and 90-second/global350 limits. Each service group must additionally bind first/second lookup caller and its derived L/P, EBX=manager, EDI=lock, exact expected stack words, original CALL/IAT target and raw context. No site may consume observations outside the open gain call; incomplete, nested or out-of-order groups fail closed. Shared `4a7a05` is one observation completing Enter and beginning GetCurrentThreadId, not two fabricated stops.

Five game sites cover Enter, GetCurrentThreadId and Leave for each lookup: at most ten service snapshots for the two retained calls. Preserve the separate worker-buffer reservation and compute actual total footprints before reads; do not increase duration, force worker calls, add sleeps, or widen the parent's temporal claim. Service rows need their own roles/counters, not fake main pending-frame identities. The final gain pair must still complete normally.

At each service site the minimum fixed existing-mode ranges are: local stack 28/24 bytes; `EDI` length24 Win32 object; `EDI+24` length8 game wrapper; the known manager root and actual owned-worker TID/backlink evidence. Capture the three actual IAT DWORDs `56e090` / `56e094` / `56e09c` and retain module/import provenance. Raw CONTEXT716, actual CW/MXCSR and existing thread FS metadata remain necessary. The game wrapper and manager/vector observations are validation inputs/diagnostics, never an implicit service write set.

An eventual adapter may apply an **observed** Enter/Leave Win32-only outcome after exact API/stack/target/TID/order and 24-byte preimage validation, preserving memory outside those 24 bytes. It must record any asynchronous OS synchronization uncertainty; capture timing does not prove the calling thread alone caused every lock-bit change. Unexpected wrapper, vector/header, source or other game-owned mutations remain separately unbound producer changes. For GetCurrentThreadId only the actual caller ID is the defined result: changes in lock bytes across that service cannot be attributed to this getter. Preserve the strict stop for such changes rather than transplanting waiter or game-wrapper values. Full private volatile-register/callee-stack equality remains a separate obligation; capture raw returns instead of inventing values.
