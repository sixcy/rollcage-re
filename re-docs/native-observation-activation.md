The opt-in host policy is:

```json
{
  "observationActivation": {
    "breakpointId": "controlled-recovery-caller",
    "rawHit": 229,
    "observationBreakpointIds": ["the explicitly declared24 nested IDs"]
  },
  "pendingFrameObserver": {

```

The site list above is abbreviated for explanation; the actual services-deferred
preparer emits all24 exact IDs. At process creation, those sites are resolved
and their original bytes retained, but their instructions remain unpatched.
After the trigger snapshot and every declared guard/write completes, the
debugger validates the unchanged original code and arms the observers while
the debug event still stops the owned process. The original trigger CALL has
not executed yet. No game-owned instruction or return value is supplied.

`frame-thread` permits nested snapshots only while a pending parent is active
and on that parent's actual thread. Other threads and outside-parent calls
still execute their original instructions; they neither read snapshot ranges
nor consume the nested/global snapshot budget. Raw-hit counters include those
postactivation traps. Matching counters advance only after scope admission
and the declared byte predicate. The actual skips and their reason are logged.

The helper rejects unguarded/filtered/stopping triggers, duplicate/unknown sites
and nonnested activation targets. Failed guards arm no sites. If code changed
before a later site can be activated, the partial attempt fails; terminal
cleanup restores only debugger-owned armed sites and records byte readback.
Defaults and older configurations retain their previous behavior.

`services-deferred` is a new explicit preparation mode; existing `services`
remains unchanged. Its90-second,350-snapshot,115-nested and128MiB pending limits
are unchanged. The read-only verifier checks actual deferred-installation,
guard, activation, completion and parent ordering, actual zero-hit code state,
and same-thread nested records. The controlled recovery verifier independently
checks the original four dynamic guard addresses and first-body input.

Focused native fixtures prove untrapped preactivation instructions, successful
guard ordering, no activation on a failed guard, byte-verified cleanup after
partial activation, and a two-thread handshake in which background instructions
execute while only parent-thread observations consume the snapshot budget.
Existing queued/re-deferred breakpoint handling remains necessary after arming;
it preserves each original instruction and one eventual observation.

These are host-tooling and synthetic native-fixture results. A new original-game
capture is still required before the deferred profile supplies game fidelity
evidence. This component does not establish native wall-clock timing or prove
that physical keyboard/mouse input cannot affect the game.
