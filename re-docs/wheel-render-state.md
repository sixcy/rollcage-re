# Wheel render preparation

`src/wheel-render-state.mjs` implements complete `41d2b0` and all reached numeric helpers. `prepareVehicleWheelRender(bodyAddress, {memory, scratchBase})` uses raw shared body, wheel and linked render-object storage. No game callback or imported service is required. `scratchBase` is native entry ESP.

The parent reads steering `body+644`. Only mode byte `718 == 8` smooths the cached steering `648`, using separate signed divisions of target and previous values by four before their difference is added. Other modes use target steering directly and preserve the cache. It copies five DWORDs from `body+c4` to short matrix scratch `91d360`, including the padding short, and converts nine signed entries to float32 rows at `91cdc0` using original scale `5dc5f4`. Float row padding remains untouched.

Four 200-byte wheel records begin at `body+324`. Only the first two receive steering; the rear pair receive zero. Actual `41d460` reads each linked render object through wheel `+6c`, combines a fixed quarter-turn with steering and spin, and calls actual `432680`. Reversal negates steering and spin only when `body+64f == 1`; the separate position-offset helper distinguishes zero from any nonzero orientation byte.

The original 4,096 phase pairs at `570720` are retained verbatim in `src/render-angle-table.json`. Angles wrap through their low 12 bits. These values have asymmetric endpoints, including -4095 where an idealized trigonometric replacement would produce -4096. Low-32-bit products, shifts, output-short wrapping and the untouched two-byte matrix gap are preserved. Actual `433400` transforms each local matrix column through the body matrix, writes scattered short scratch fields without replacing their upper words, and publishes the linked object's nine matrix shorts.

Actual `41d610` halves the wheel's signed short accumulator toward zero, applies contact displacement from `+80` when flag bit 0 is set, writes the wrapping accumulator short, and derives a separately clamped offset from the full pre-truncation value. The clamp is -6..6. It copies wheel `+70..77` into renderer short-vector scratch. Existing actual `4334b0` transforms that vector. Finally the child copies live parent spatial pointer `+c` and terrain reference `+11c`, then adds transformed offsets shifted by 16 to the parent's live world position. A linked render object may alias its source body; subsequent wheel calls observe the resulting body writes while retaining the parent-captured matrix scratch.

Public helpers are `prepareWheelRender(wheelAddress, bodyAddress, steering, runtime)`, `buildRenderRotationMatrix(anglesAddress, outputAddress, runtime)`, `transformRenderShortVector(runtime)` and `updateWheelRenderOffset(wheelAddress, bodyAddress, runtime)`. `initializeWheelRenderTables(memory)` maps the original phase table and float scale; it does not invent body or render-object constructors.

## Producer ownership

Existing actual `42a9a0` produces steering `644` from the byte control axes. The connected comparison runs that producer before the wheel render parent. Existing wheel physics advances angle `+78`. Actual contact processing `488910` commits orientation byte `64f` after a successful contact attempt, retaining the original value if both attempts miss; suspension processing copies distance to wheel `+80`.

Retained constructor `41caf0` claims each wheel render object through `4741c0`, stores it at wheel `+6c`, and sets its `+164` back-pointer to the wheel. It initializes spin/angle, authored short offsets `+70..74` from `5eac40+8*index`, distance `+80 = 240000`, and final body orientation byte `64f = 0`. It also initializes wheel geometry and force coefficients through additional game routines. This package traces that ownership but does not claim the entire constructor/model-loading graph as implemented. Caller-owned valid linked objects and authored offsets remain explicit inputs.

## Validation

`node tools/verify-wheel-render-state-instructions.mjs` passes **399 retained instructions for the complete render graph**, plus the existing input producer, **2,400 mixed fixtures**, **120 producer chains**, **2,640 top-level calls**, and **1,712,987 interpreted steps**. The connected run reaches 455 distinct instructions: 920 full render parents, 4,080 wheel children, 4,480 matrix builders, 12,640 short transforms, 4,480 offset updates and 4,080 existing offset transforms. There are no external calls.

The comparison covers the entire declared non-stack memory, including full bodies, all linked objects, matrix/renderer scratch and untouched neighbors. Cases include signed boundaries, wrapping steering/spin, reversal, zero/nonzero contact, negative division, pre-truncation clamp behavior, original phase bytes, matrix overflow and source/render-body aliases. Seven focused tests pass with `node --test tests/wheel-render-state.test.mjs`.

Primary report: `analysis/wheel-render-state-complete-instruction-check.json`. The earlier `wheel-render-state-instruction-check.json` is retained as the preliminary mixed-fixture run, not additional coverage. Evidence comes from retained `281`, `1501`, `1505`, `1507`, `1509`, existing `1180`, original-byte reads `1510/1511`, and constructor ownership `1530/1531`; target SHA-256 and instruction/table evidence IDs are recorded in the primary report. These are interpreted shipped instructions over synthetic mapped runtime inputs, not original-process or rendered-wheel observations. Reused input and matrix helpers overlap other reports.
