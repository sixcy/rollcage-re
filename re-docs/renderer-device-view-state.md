# Renderer device view state

`src/renderer-device-view-state.mjs` implements actual transform-state constructor 50ef40 and game-owned rectangle adapter 511380. The constructor owns seven identity matrices, scalar/vector fields and its final dirty flag. It uses actual lazy identity 402160 and preserves sequential block copies, including overlap with shared identity storage.

The rectangle adapter copies the original four-word rectangle into device+4ech before reloading four input words into its six-word native viewport descriptor. It calls the actual lower Direct3D SetViewport interface, then reloads the private descriptor, converts its four unsigned32 fields to binary32 and constructs the screen matrix at device+234h. Decompiler output incorrectly described those conversions using incoming ESI/EDI; retained assembly proves the private rectangle fields are their real producers.

`services.d3d9Call(device,0xbc,[viewportDescriptor],runtime)` is a genuine platform/COM boundary after the recovered game adapter. Its ownership is traced through actual 510080, which calls Direct3DCreate9 and stores its interface at device+368h, and 512a30, which calls that interface's CreateDevice slot40h with output device+36ch. The rectangle's slotbch is IDirect3DDevice9::SetViewport. In contrast, device+364h is a separate game-owned state-cache wrapper and remains unported; its methods must not be labeled direct platform calls.

`analysis/renderer-device-view-state-instruction-check.json` passes 2,400 fixtures, 192 reached instructions and 271,200 interpreted steps, including 1,200 ordered Direct3D requests and 1,860 alias cases. All mapped memory at or above 10000h, defined EAX, original literal bytes and ordered viewport payloads match. It includes unsigned extremes, same/partial input overlap, shared identity overlap, three entryESPs and explicit service mutation of a native private width word to test live reload. Four focused tests check identities, viewport request order, screen matrix values, unsigned conversion and a reduced native comparison.

Device constructor 50f510 and its real resource pools are now implemented and verified; see renderer-device-construction.md. Initialization/bootstrap 519df0/510080, state-cache adapters, shader and post-processing graph remain unfinished. The existing viewport preparation parent still declares its remaining game-device contracts. These leaf algorithms are not a full renderer claim. No original game or graphics-device execution was used.
