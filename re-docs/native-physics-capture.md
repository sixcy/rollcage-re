# Windows native physics capture adapter

`tools/native-physics-capture.ps1` launches exactly one declared x86 executable through Windows `CreateProcess(DEBUG_ONLY_THIS_PROCESS)`. It owns that process, records native debug events, and captures explicit memory ranges and x86 registers at software breakpoints. REA's available native runtime lane does not supply this Windows memory tracing. These captures are a separate evidence source.

The helper compiles with Windows PowerShell `Add-Type`; it needs no downloaded packages, debugger installation, or administrative rights by design. A client sandbox can independently require process-launch approval. A compile check and configuration validation do not launch the target:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/native-physics-capture.ps1 -CompileOnly
powershell -NoProfile -ExecutionPolicy Bypass -File tools/native-physics-capture.ps1 -ConfigPath C:\workspace\capture-config.json -ValidateOnly
```

`-ExecutionPolicy Bypass` applies only to that child shell; it does not change the user's execution policy. Respect any managed organizational policy. Actual capture uses the same command without `-ValidateOnly`. The game should only run from a reviewed isolated workspace copy, after its writable paths and external services have been accounted for. Installed assets remain read-only.

Pass `-Quiet` for an actual capture to suppress stdout's JSONL mirror while preserving the fully flushed `trace.jsonl`. Validation still prints its short completion message. Quiet mode changes only console output.

## Unattended Redux scenarios

The user should leave capture operation to the agent: **no Start press or driving is needed**, unless a later experiment explicitly requests manual input. Announce capture start and completion. For clean measurements ask the user to pause keyboard/mouse use only during the capture: hidden/no-activation windows do not establish input isolation, especially when the game is deliberately given a substituted foreground observation. Ordinary source work and tests require no such pause. The [read-only input audit](native-capture-input.md) identifies DirectInput and message/state-query channels, while preserving uncertainty about background acquisition and outer input effects; no input-neutralization hooks are installed. Earlier runs did require external launcher input; their provenance is retained separately.

`node tools/prepare-native-physics-capture.mjs INSTALLATION NEW_DIRECTORY` copies and verifies the installation and prepares three bounded configurations from `tools/lib/redux-capture-scenarios.json`. The default `capture-config.json` stops at post-CRT WinMain before game windows. `hidden-device-boundary-config.json` skips the launcher/movies and stops before the Direct3D device call; `hidden-idle-config.json` continues through the native idle route to the first physics call. The two hidden policies match retained successful native configurations; path fields are rewritten for the new isolated copy. The default and named post-CRT configs share an output directory and are alternatives, not two successive runs. Every actual rerun needs a fresh output path.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/native-physics-capture.ps1 -ConfigPath NEW_DIRECTORY\hidden-idle-config.json -Quiet
```

The hidden idle scenario completed without user input: six native AI participants, first physics entry with x87 PC24, hidden/windowed guards active, and owned-process termination. Evidence: `analysis/physics-native-hidden-idle-20261022/`. This establishes unattended capture operation, not original-process trajectory equivalence.

It verifies call/return sites against retained instruction evidence, observes complete preparation/force/derivative boundaries and vehicle steering-direction, suspension, rest, airborne-spin and orientation stages, and stops at the declared `4749e0` return. No simulation values or AI inputs are overwritten. Its bounds can still end an incomplete run; the replay checker requires the expected terminal frame count.

`node tools/check-native-body-replay.mjs CAPTURE_DIRECTORY NEW_REPORT_DIRECTORY` verifies native blob/context hashes and pairs same-thread/same-body entry/exit observations. Recovered skipped-call flags are recorded explicitly. Native pointer bytes remain opaque and unchanged. Native ABI stack/global scratch is outside this comparison. Only selected 384-byte numerical body pairs are published as regression fixtures; extended raw snapshots remain local.

The ten-frame report `analysis/physics-native-vehicle-stages-20261022/` matches 610 stage comparisons exactly. Host keyboard/mouse activity was not logged; this proves replay from those recorded inputs, not an input-isolated end-to-end trajectory. Whole-frame collision and gameplay acceptance remains open.

Terrain queries use `tools/prepare-native-terrain-capture.mjs ISOLATED_ROOT NEW_CAPTURE_DIRECTORY NEW_CONFIG_FILE [REGULAR_RETURNS=1]` (1..32). It builds sectors from live captured headers and vertices, not installed geometry. The first one-query native report matches exactly but records a ray miss, not a successful contact (`analysis/physics-native-terrain-replay-20261022-reviewed/`).

Optional arguments after the count select `all|body` and `any|active`. Body mode observes exact `424ed7`/`424edc` call sites around the car/body-sphere batch. Active mode uses an observer-only `captureWhen` condition on native session `+57c == 4`; earlier queries execute normally but are not snapshotted. Every captured pair retains the actual race phase, attract byte, logical clock and caller boundary. The synthetic gate runtime check (`analysis/native-capture-gate-20261022/verified/`) verifies a skipped first hit, successful second hit and owned-child termination.

The active-race wheel/body batch matches **32 queries, including 24 successful wheel ground contacts and eight body-sphere misses**, with exact fractions, the complete output/query/body/candidate spans and all declared shared scratch (`analysis/physics-native-terrain-active-wheel-20261022/`). The separate body-only active batch matches sixteen sphere misses. Earlier menu/startup probes are labelled separately; hearing menu audio does not establish race phase. These captures are individual query comparisons, not full races or complete collision/handling equivalence. All 171 original installed files and copied original-file paths retain their hashes after the active wheel capture.

`tools/lib/captured-memory.mjs` provides replay access only to explicitly captured regions. Equal overlapping bytes merge; disagreement, uncaptured reads/writes, ambiguous aliases and address/byte-bound overruns fail. Preferred-address global spans have explicit aliases into their actual ASLR addresses; native heap/query pointers are not rewritten. Source subarrays share those captured bytes, preserving numerical aliases. Backing-store identity and generic whole-Buffer operations across disjoint regions are deliberately unsupported. Raw geometry remains ignored/local; portable reports retain hashes and selected numerical results.

## Configuration contract (schema version 1)

The JSON configuration requires `executablePath`, `workingDirectory`, `expectedSha256`, and a new absolute `outputDirectory`, whose parent must already exist. `arguments` is an array of individual command-line arguments. `maxDurationMs`, `maxEvents`, and `maxSnapshots` are positive hard capture bounds; their defaults are 60000, 100000, and 1000. `showWindow` defaults to false. A process PID is emitted immediately in the `owned-process` stdout/JSONL event; any separately authorized UI interaction must target that PID specifically.

`breakpoints` contains unique `id` values, exactly one `rva` or absolute `address`, optional `ranges`, and optional `stopAfterHits`. An RVA is resolved against the `CREATE_PROCESS_DEBUG_EVENT` main-module base. Decimal and `0x` strings are accepted for addresses. The first original byte is preserved in the trace before installing `INT3`; original `INT3` bytes and overlapping breakpoints are rejected. Return-stage snapshots use explicit recovered return-site RVAs; dynamic function-return discovery is not implemented.

A breakpoint may add an observer-only `captureWhen` predicate, for example `{"range":{"id":"session-phase","rva":"0x1ecb1c","dereferenceOffsets":["0"],"offset":"0x57c","length":4},"equalsBytesHex":"04000000"}`. The range uses the same explicit root/chain resolution, must have fixed length 1–64 bytes, and must exactly match the expected raw bytes. Region predicates and `phaseActions` referencing filtered breakpoints are rejected. No predicate writes occur. A failed predicate read stops capture; it is not treated as a nonmatch. Apply independent entry/exit predicates when pairing a pure query across an observed phase.

On a nonmatch, `observation-skipped` records `breakpointId`, one-based `rawHit`, `tid`, `predicateAddress`, `actualPredicateBytesHex`, and `expectedPredicateBytesHex`, with `reason: "predicate-not-equal"`. These rows are bounded by the existing event/duration limits. The original instruction still executes through normal restore/single-step/rearm, without snapshot blobs, snapshot ordinal advancement, or `stopAfterHits` advancement. A filtered snapshot adds `rawHit`, `matchingHit` and `captureWhen: {address, actualBytesHex, equalsBytesHex}`; its `hit` counts only completed captures at that breakpoint and `stopAfterHits` uses that count. Unfiltered snapshots retain their existing fields and one-based hit semantics. Service guard breakpoints are independent of these observation predicates.

Optional `skipMatchingHits: N` skips the firstN successful equality matches. It requires `captureWhen`, even for an explicit zero value, and rejects negative/fractional counts. The internal matching counter advances only after a true predicate; skipped matches emit `reason: "matching-hit-window"`, `matchingHit`, `skipMatchingHits`, raw hit and exact predicate bytes. They execute the original instruction normally and do not advance snapshot hit/stop bounds. Thus skip60 followed by a first capture has `hit:1, matchingHit:61`; `rawHit` additionally includes every false phase predicate. This selects a later native observation window without target writes or fabricated progress.

Optional `captureThreadEnvironment:true` captures the stopped owned thread's original FS:[0] SEH head in every immediate or deferred snapshot. The helper reads the FS selector from context DWORD144, queries its actual descriptor with `Wow64GetThreadSelectorEntry` on a64-bit host or `GetThreadSelectorEntry` on a32-bit host, decodes BaseLow/BaseMid/BaseHi from descriptor bytes2..3/4/7, and reads exactly four bytes at that base. It uses no guessed TEB layout or global process sweep. Selector/descriptor/base validation, query failures and failed reads stop capture; no alternate root or zero value is substituted. Defaultfalse keeps existing captures unchanged.

The snapshot adds `threadEnvironment:{fsSelector,descriptorHex,fsBase,sehWord,tid,selectorApi,contextSelectorOffset:144,source:"stopped-owned-thread-selector-query"}` and an ordinary hashed four-byte range with reserved id`thread-seh-head` at the observed FS base. Its bytes and metadata must agree; the raw716-byte context independently retains the selector. Deferred host-buffer admission reserves these four bytes before any range payload reads, and committed budget proof includes the extra range. This observes the SEH head only, not the complete TLS/TEB state or every exception/service context.

Snapshot range failures now include structured `capture-error.rangeFailure` diagnostics in both immediate and deferred readers: descriptor id/root/chain/offset, failure stage (`resolve-root`, `query-readable-region`, or `read-bytes`), resolved root/read span when known, and declared bounds. A failed region query/validation additionally preserves returned information length and actual region base/allocation base/size/state/protection/type when available. The same detail is included in the exception text for PowerShell output. These diagnostics do not retry, substitute bytes, relax protection checks, or convert errors into skipped observations.

Microsoft documents the [selector query](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-wow64getthreadselectorentry), [eight-byte descriptor fields](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-wow64_ldt_entry), and [WOW64 context segment fields](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-wow64_context). The synthetic `thread-environment` mode stores actual FS:[0] and the FS selector before its breakpoint; `pending-thread-environment` stores actual FS:[0] before either candidate frame. Checker modes with those names compare fixture bytes, descriptor-derived base, raw context selector, hashed head bytes, and pending payload budget. These fixtures must be executed separately by the authorized operator; generation, compilation and configuration checks launch no process.

Executed synthetic evidence for this window is `analysis/native-capture-window-verified-20261022/`: two skipped true predicates, then counter3 captured as hit1/raw3/matching3, snapshot-bound completion and owned-process termination. Later game windows use skip60 and120 to retain complete entry/return pairs. They prove their reached state, not guaranteed impacts at those clocks. `tools/prepare-native-event-frame-capture.mjs` adds bounded474bb0 observations at one explicit clock; its first clock348 attempt had no events and therefore provides no positive dispatch-stream evidence. Direct event verification must reject an empty selection rather than treat empty-list agreement as collision coverage.

Optional `pendingFrameObserver` selects an observed dispatch inside a complete frame without guessing its clock. It declares `beforeBreakpointId`, `afterBreakpointId`, `eventBreakpointId`, `maxPendingBytes` (at most128MiB), `maxCandidateFrames` (1..10000), `maxEventSnapshots` (1..64), `eventStackOffset`, `eventReturnRva`, `eventPointerRegister`, `eventRecordBytes`, and fixed-four-byte `eventPoolRoot`/`eventPoolCapacity` descriptors. The three ids must be distinct. Entry/event cannot stop independently; after must declare `stopAfterHits:1`, entry/after matching skip windows must agree, and no phase action may reference these observers. Event `captureWhen` remains available for explicitly narrower selections; a full dispatch-stream verdict requires no event filter.

After the normal phase/skip test, each candidate entry reads its complete snapshot into host RAM. The budget counts context716 bytes and every declared range, including duplicated regions, and is reserved before reading full blobs. Event calls must share the frame thread, have the exact declared stack offset and return word, and select an aligned record inside the explicitly captured pool capacity. Every event call is counted and ABI-checked; only qualifying events are buffered. A matching after with no qualifying event discards the RAM candidate. A qualifying after buffers the full exit, writes every immutable blob first, then publishes ordered before/events/after rows and stops. No target-side latch or gameplay write is used. Unexpected nesting, foreign-thread events/exits, changed caller/stack/matching counter, failed reads, exceeded bounds, or a terminal stop with an incomplete frame fail explicitly. The candidate limit stops after its last discarded exit, before another entry.

Deferred snapshots retain `rawHit`/`matchingHit` from observation, advance `hit`/ordinal only at commit, and add `deferredPublication:true`, `observedElapsedMs`, `observedDebugEventOrdinal`, and `pendingFrame`. That proof contains `candidateIndex`, `role`, `frameTid`, `frameEntryEsp`, `frameReturnAddress`, `frameMatchingHit`, final `observedEventHits`, and final `qualifyingEventSnapshots`; event rows additionally contain one-based qualifying `eventIndex`. All published rows carry the final group totals. Trace events are `pending-frame-started`, `pending-frame-event`, `pending-frame-discarded` (`reason:no-qualifying-event`), and `pending-frame-selected` (first/last committed ordinals). Completion also retains `pendingFrameSelection`. Matching counters continue across discarded candidates, so an accepted frame has `matchingHit = skipMatchingHits + candidateIndex`, while its committed frame `hit` is1. Trace publication time is separate from observation time. A disk failure may retain partial immutable files, but the capture has an error and cannot be admitted as a complete frame.

`pending-frame-config.json` is a separately generated synthetic fixture: first candidate has no event, second calls a real event with ESP below the parent by28 and ECX selecting its sole104-byte pool record. Its expected committed counter values are `[1,2,2]`, raw hits `[2,1,2]`, and committed hits `[1,1,1]`. `tools/check-native-capture-fixture.mjs FIXTURE_DIRECTORY NEW_REPORT_DIRECTORY pending-frame,matching-window` verifies deferred pairing and the pre-existing immediate path. Generation/configuration checks launch nothing; original-process or synthetic runtime evidence must be retained separately.

`pending-filtered-config.json` uses a separate fixture executable with only the conditional branch at file24d changed from `7515` to two NOPs. Both candidates therefore call the actual event; its observer predicate reads counterRVA1100 and accepts exactly `02000000`. The first candidate records one observed event but zero qualifying snapshots and is discarded; the second retains one qualifying event. Expected raw hits are `[2,2,2]`, matching hits `[2,1,2]`, and counter bytes `[1,2,2]`. Checker mode `pending-filtered` requires the false event's predicate/ABI trace, the discarded candidate, and the accepted complete group. This validates the filtered-substream mechanism, independently of any game event-kind interpretation.

Global `ranges` are included in every gameplay snapshot; breakpoint-local ranges apply only to that stage. Each range requires an `id`, `length`, and exactly one absolute `address`, main-module `rva`, or `baseRegister`. An RVA starts at the observed main-module base plus that RVA, before applying any pointer chain; this preserves explicit mappings under ASLR. A register root names a captured x86 register, such as `esp` or `ecx`. An optional `dereferenceOffsets` array implements an explicit pointer chain: start at the root, read an unsigned little-endian 32-bit pointer at `current + eachOffset`, then add the final `offset`. The final offset and pointer-chain offsets accept signed decimal or hexadecimal strings. No pointer identities are guessed from integer values.

For an explicitly selected variable-size game buffer, a range may instead use `readableRegion: true` and positive `maxRegionBytes` (at most 64 MiB), with `length` omitted/zero. The helper makes one `VirtualQueryEx` call at that resolved root and captures exactly the returned `BaseAddress`/`RegionSize`, only when the complete region is committed, readable, unguarded, within the declared bound, and wholly inside the x86 address space. PAGE_NOACCESS, PAGE_GUARD, execute-only, reserved/free, oversized and unreadable regions fail before that region is captured. There is no process sweep or fallback read beyond the returned region. Fixed-length ranges preserve their previous behavior and must not specify a region bound; `foregroundWindowSource` remains fixed length4.

For example, the explicit geometry-pointer root can use `{"id":"geometry-region","rva":"0x50b970","dereferenceOffsets":["0"],"readableRegion":true,"maxRegionBytes":16777216}`. The trace preserves `requestedResolvedRoot` separately from actual range `address`/`regionBaseAddress`, plus region size/protection/state/type and bound. A queried virtual-memory region is not proof of a complete logical heap allocation or its authored object size; consumers must use the recorded root's offset within the returned bytes. The [Windows region structure](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-memory_basic_information) and [VirtualQueryEx contract](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-virtualqueryex) define those page-region semantics.

For example, a racer-body global pointer and entry stack can be captured as:

```json
{
  "id": "physics-entry",
  "rva": "0x50e50",
  "ranges": [
    {"id": "body0", "rva": "0x509300", "dereferenceOffsets": ["0"], "length": 15992},
    {"id": "stack", "baseRegister": "esp", "length": 64}
  ]
}
```

`phaseActions` optionally declares writes at an exact `breakpointId` and `hit` (one-based). Each write uses the same address resolution fields, plus `bytesHex` and exactly one original-byte policy: `expectedBytesHex` or a nonempty `expectedAnyBytesHex` array. Every accepted candidate must have the replacement's length. A mismatch stops capture before the write; the trace retains the exact original bytes and accepted policy. Writes overlapping any observation breakpoint are rejected. Snapshots precede these interventions. This is instrumentation, not evidence of unmodified native state.

## Service adapters and isolation limits

The following settings are optional and explicitly change startup services. They do not establish original initialization equivalence:

- `redirectedDocumentsPath`: existing absolute ASCII directory, shorter than `MAX_PATH`; emulates imported `SHGetFolderPathA` calls whose folder ID's low byte is `CSIDL_PERSONAL` (5). It writes the declared path, returns `S_OK`, and skips the native call. Other folder IDs execute the original API.
- `redirectedShellFolderPath`: same path constraints; emulates imported `SHGetPathFromIDListA` conversions. All returned legacy paths share this isolated root, including known Documents/AppData paths. Real PIDLs are still allocated and freed by native shell services. The original distinction between those roots is deliberately not preserved.
- `denyRegistryWrites`: denies imported `RegSetValue[Ex]A/W`, `RegCreateKey[Ex]A/W`, `RegDeleteValueA/W`, `RegDeleteKeyA/W`, and `RegUnLoadKeyA/W` with `ERROR_ACCESS_DENIED`. Denying key creation can also prevent configuration reads through a helper that first creates/opens the key; capture must record resulting defaults.
- `denyChildProcesses`: denies imported `CreateProcessA/W`, `WinExec`, `ShellExecuteA/W`, and `ShellExecuteExA/W`. This excludes music-player and restart children from the capture; return values indicate failure. It does not synthesize thread `GetLastError` state.
- `denyPlayerMailslot`: intercepts imported `CreateFileA/W` only for the case-insensitive path `\\.\mailslot\Rollcage Player`, returning `INVALID_HANDLE_VALUE`. Other opens execute natively. This prevents commands reaching a player that was already running; child-process denial alone does not cover that channel. It does not synthesize thread `GetLastError` state.
- `temporaryDirectory`: existing absolute directory below `MAX_PATH`; passes a child-only Unicode environment block with `TEMP` and `TMP` overridden. Other variables are retained without being logged. The parent environment is unchanged.
- `hideOwnedWindows`: opt-in main-import policy that strips `WS_VISIBLE`/`WS_EX_TOPMOST` and adds `WS_EX_NOACTIVATE` to native `CreateWindowExA/W`; forces `ShowWindow` to `SW_HIDE`; removes `SWP_SHOWWINDOW` and adds `SWP_NOACTIVATE|SWP_HIDEWINDOW` in `SetWindowPos`. Native window creation and those calls still execute. `SetFocus`, `SetForegroundWindow` and `SetActiveWindow` are skipped with zero return. Each argument edit records the API, stack slot, original/replacement bytes and reason; skipped activation requests retain stack/register state. It is disabled unless explicitly requested.
- `foregroundWindowSource`: optional memory-range descriptor with `length: 4`, used only to resolve an HWND for emulating imported `GetForegroundWindow`; it does not add a captured blob. The helper reads that explicit root/chain/offset, requires a nonzero HWND verified by `GetWindowThreadProcessId` to belong to the owned child, and returns that HWND without changing OS focus. Before the first valid owned window exists, null source pointers/zero HWNDs defer the adapter and execute the original read-only query, recording `foreground-adapter-deferred`. Only unavailable-memory `ReadProcessMemory` errors 299/487/998 admit that early fallback; unrelated errors fail. Any nonzero foreign/stale HWND fails, and a source that disappears after successful initialization also fails. Every substitution records the actual host foreground HWND from an unmodified API query, the substituted HWND, resolved source address, and register/stack changes. Example for the recovered Redux application root: `{"id":"application-hwnd","rva":"0x2efb38","dereferenceOffsets":["0"],"offset":"4","length":4}`. This changes the game's foreground observation deliberately; it does not activate a real window.

The helper parses the main executable's import table, logs all imports and resolved IAT targets at the x86 loader breakpoint, and patches selected API entries before WinMain. Under WOW64 the earlier 64-bit loader breakpoint occurs before PE32 imports are resolved and is continued without installing service hooks. `STATUS_WX86_BREAKPOINT` (`0x4000001f`) and `STATUS_WX86_SINGLE_STEP` (`0x4000001e`) are handled alongside standard exception codes. Register state, stack bytes, skipped calls, original output bytes, and replacement bytes are retained for every adapter invocation. Missing required folder imports, missing registry coverage, reaching a declared stage before required hooks, or overlapping hook targets fail capture. Hooks apply at the resolved API address process-wide, even when another module calls it. Dynamically resolved functions and APIs imported only by other modules are outside the declared coverage. This is not a general Windows security sandbox. The caller must separately isolate temporary paths and audit remaining filesystem/device operations.

The hide policy alone does **not** establish that a capture cannot take over the display. The original frontend overrides command-line windowed settings, modal dialog internals can bypass public imported window functions, and exclusive Direct3D presentation is a separate boundary. The validated hidden scenarios combine the native skip-launcher/movie settings with explicit game/device windowed presentation guards before the real COM device call, preserving native FPU flags. The boundary probe and full hidden idle run are retained under `analysis/physics-native-hidden-device-20261022/` and `analysis/physics-native-hidden-idle-20261022/`.

Under `hideOwnedWindows`, declared main-import `DialogBoxParamA/W`, `DialogBoxIndirectParamA/W`, `MessageBoxA/W`, `MessageBoxExA/W` and `MessageBoxIndirectA/W` are fail-closed boundaries: reaching one emits `unexpected-modal`, records its stack/register inputs, and aborts capture before the original API executes. The helper supplies no synthetic dialog result and clicks no controls. The known launcher must be skipped through its recovered native option; an unexpected startup error stops rather than opening a dialog. This guard shares the import-coverage limits above.

## Trace and lifecycle

`configuration.json` preserves the original configuration bytes. `trace.jsonl` is flushed after every event; stdout mirrors it. Each snapshot records registers, x87 control/status words, MXCSR, raw 716-byte x86/WOW64 context, and raw memory blobs with addresses and SHA-256 digests. Capture reflects a conceptual instruction boundary before the displaced original instruction: EIP is rewound from `INT3` to the original instruction address. Main/DLL module paths and bases are recorded when available.

For a startup stall, opt into `captureThreadsOnStop: true` and optional `stopThreadStackBytes` (default 128, admitted 0–512). Before cleaning up a still-owned process, the helper temporarily suspends each tracked owned thread, records its WOW64 context and available ESP stack bytes, and restores exactly the diagnostic suspension increment. Thread rows retain PID, TID and main-thread identity; raw context/stack blobs have exclusive filenames and SHA-256 digests. Read/context/write/suspend/resume failures are explicit best-effort diagnostic errors and do not replace the capture's existing result or prevent cleanup. A naturally exited process is reported as unavailable for these diagnostics. These are unordered stop samples, potentially inside system wait code; they are separate from logical physics-stage snapshots.

After a normal breakpoint hit, the helper restores the original byte, suspends peer threads, executes one original instruction with the trap flag, reinstalls the breakpoint, and resumes peers. At bounds or failure, diagnostic suspend increments are restored first, then terminal cleanup freezes every tracked owned thread (and the main-thread handle if not yet tracked). Guard bytes are restored only if every cleanup freeze succeeds. If any freeze fails, remaining guards stay installed until the owned child is terminated. Terminal freezes are never resumed into an unguarded runnable process. Termination runs in a `finally` even if freezing, logging or restoration fails. The trace declares this cleanup policy and records freeze outcomes. The helper never detaches a process containing observation patches. A natural child exit is continued and recorded. Errors, cleanup failures, and unhandled exceptions remain in the trace. Existing capture directories are never reused.

Debugger pauses and single-stepping perturb wall time. Trace elapsed time must not be used to infer native simulation cadence. Exact clock fields captured at logical stages are valid observations of the instrumented execution.
