# Registered renderer window callback and key producers

`src/renderer-window-messages.mjs` reconstructs registered window procedure `50d640`, the actual Application message receiver `403570`, and reverse key-history parser `4416a0`. It uses original Application/settings singleton algorithms and exact original vtable targets. Evidence: retained 13392/13393, 13414/13415, 13424/13425 and the original key-string bytes 13426. The same Redux SHA-256 `c0582271862ec373f00d01545c2a95aef0abb10a32513ec585271d08b10c6cf5` applies.

The procedure resolves the live WindowsApplication through actual `402aa0` and CRT RTTI before capturing its incoming message arguments. Actual `403570` consumes `WM_CLOSE` without setting the quit flag, and consumes `WM_KEYDOWN` after passing only the low key byte to `4416a0`. Destroy resolves Application again, obtains actual virtual `10h`'s zero and calls `PostQuitMessage(0)`. Other messages reach original numeric fullscreen command filters, power-broadcast magic `424d5144`, or `DefWindowProcW`. Fullscreen must equal byte one, and command filtering compares complete DWORD values without masking low command bits. Unknown Application overrides remain explicit game gaps.

Key history shifts the previous 32 bytes backward, prepends the new key byte, sets byte 32 to NUL, then invokes genuine CRT `_strlwr` and `strstr`. A match must point to the history's first byte. The two independent pattern families preserve all original gates and ordered field widths: gravity/mode values, configuration toggles, session byte flags, horn WORD and jet DWORD. Complement/XOR sequences for the speed/network flags toggle only bit seven. The boolean cheat uses zero/nonzero conversion, not a blind XOR. Recognized commands invoke actual `484bb0` with feedback code 35 and its real `40ea40` dispatcher.

`tools/verify-renderer-window-messages-instructions.mjs` passes **6,300 calls, 660 reached instructions and 1,115,023 steps** in 900 fixture worlds. It compares all mapped bytes at and above `10000h`, defined returns, CRT/Win32 requests with child ESPs and restored FS linkage. The actual native path includes 2,058 key handlers, 1,442 feedback calls/dispatches and a persistent actual window constructor followed by three callback messages. All 18 patterns receive independent enabled/disabled gates and gravity overrides. Cases include upper/lowercase keys, retained history, RTTI-side incoming-argument mutation, exact system commands, destroy and power handling. Six focused tests preserve the main rules.

The audio scope is explicit: bank absent, code outside the bank, or a null requested bank slot. Those paths execute actual `484bb0/40ea40` without a game mock. A populated feedback sound still reaches the older `sound-dispatch.mjs` libaudio game contracts; this package does not call those OS/library services or claim their closure. Root audio construction/backend work is separate. The fifth sound stack argument is unread by `484bb0`; the API assigns no gameplay meaning to its leaked volatile value.

No real OS callback, window, original executable or installed file is executed or changed. Constructor→callback sequences are declared synthetic message delivery over persistent reconstructed memory, not original-process observations.
