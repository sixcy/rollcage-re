# Renderer texture-format enumeration and selection

`src/renderer-texture-formats.mjs` implements actual51fa00 supported-format enumeration and all reached game helpers: descriptor5115f0/component reduction511500, category selection51f6b0, record append520f90, growth521260, reserve521180 and forward record copying521300. `initializeRendererTextureFormatConstants` maps original format lists and both switches from13271–13274.

Enumeration tests the original fifteen formats through Direct3D CheckDeviceFormat, appends36-byte records for successful queries, then publishes sixteen category pointers into the resulting vector. It reserves at least fifteen records but does not clear the previous logical end. Repeated initialization therefore appends duplicates and can grow storage again. If every format is rejected, category pointers still reference the reserved base; the reference preserves this native result. COM callbacks may mutate adapter/device roots between queries; allocation callbacks may mutate vector roots before copying.

Descriptors retain native field writes and byte widths. RGB masks produce component offsets and reduction shifts;511500 is an original literal switch rather than a generic bit counter:0→8,31→3,63→2,127→1 and all inputs above127→0. Unsupported formats preserve old mask/depth fields; a zero depth skips descriptor-byte recomputation. Compressed and64/128-bit floating formats follow their separate original cases.

Category selection first applies compressed-format preferences or exact floating-format searches. It then runs the original bounded depth/alpha and color passes, preserving strict ties, unsigned score comparisons, depth cutoffs, alpha requirements and the zero-index fallback. Early compressed/float success leaves the incoming category argument intact; fallback masks that argument to bit8. Vector append rebases an input record after growth. Reserve captures requested capacity, reads roots after allocation, copies in forward16/16/4-byte chunks and publishes begin/capacity/end in native order. CRT allocation/length-error branches are explicit; successful allocations and representable mapped vectors are the current interpreted proof domain.

APIs use shared `{memory,scratchBase,services}`. `enumerateRendererTextureFormats(manager,runtime)` is the actual51fa00 parent; `chooseRendererTextureFormatIndex(manager,category,runtime)` returns the native index. Actual descriptor/append/reserve helpers are exported for independent use. Only genuine Direct3D COM and CRT allocation/free remain services; no game selection callback is substituted.
