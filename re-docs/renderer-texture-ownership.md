# Renderer texture-index ownership

`src/renderer-texture-ownership.mjs` reconstructs 5208d0, 520ee0, 521030/5210d0 and allocated-index insertion 51f0f0/51f150. `obtainRendererTextureIndex(manager, output, runtime)` connects the actual texture pool at manager+48c to the corresponding integer pool at +890. Runtime contains caller-owned `memory`, native entry `scratchBase` and genuine CRT `services.libraryCall`; no graphics device executes.

Acquisition consumes the real circular free-index queue and appends the index to the allocated vector. An exhausted texture pool grows by max(oldCount/2,32), using the existing actual 513640 pool algorithm. The acquired descriptor receives a real 50ee50 temporary constructed in native private stack storage. Assignment copies defined fields and the 400h-byte area in forward DWORD order while retaining destination vtables and padding. Overlap therefore follows the native instruction sequence. When texture capacity changes, 5208d0 grows the integer pool through actual 513940 and publishes the new numeric ordinals.

Evidence is retained in replies 11402–11403 and 11408–11409 (parents), 11414–11417 and 11420–11423 (assignment/vector children), together with the existing pool evidence. All target Redux SHA256 `c0582271862ec373f00d01545c2a95aef0abb10a32513ec585271d08b10c6cf5`.
