# Renderer texture creation and release

`src/renderer-texture-creation.mjs` supplies actual renderer virtual80 (`520dc0`) and its game descendants. It preserves all eight incoming DWORD arguments and the ten-DWORD `520380` child ABI. Actual virtual98 (`50f350`) first writes the matching integer resource's ID; mode/output arguments are read afterwards and can alias that write. Native resource kind is retained before association. Unknown mode returns false after clearing the output byte.

The resource creation parent chooses original formats, shifts/clamps dimensions, applies compressed four-pixel limits, computes signed mip counts, writes native fields and calls actual resource virtual14 (`51f690`). Cube resources become square. Modes3/4 choose depth formats through actual `511a30/510f60` and the original preference tables; both Direct3D adapter queries execute in the native order. Original constants and switch bytes are retained in `renderer-texture-creation-constants.json`; `initializeRendererTextureCreationConstants(memory)` publishes them when a caller constructs its raw runtime without the retained program loader.

`5207a0` distinguishes unsigned cap comparisons from signed power-of-two searches. It also preserves a subtle alias: the height comparison precedes the width store, but the conditional memory load follows that store. Shared dimension pointers therefore sometimes read the newly stored width, and sometimes retain the captured cap. The source keeps this order instead of reducing it to two independent minimum expressions.

`520660` implements surface allocation policy and exact Direct3D device method5c/60/64 and optional depth-surface74 arguments. Secondary allocation aliases the primary only when byte45d is exactly1. Failed primary allocation reaches actual `51ef10→50f280→50eed0`: secondary, depth and primary surfaces are released in order with sharing handled explicitly. Actual `526a90` walks the populated binding-cache owner/vector and live44-byte rows, unbinds matching textures through device methodd0 and clears only the native cache fields. No game-owned release callback substitutes for these algorithms.

The sole device interface is `services.direct3DCall(object,method,args,runtime)`: `args` contains every native stack DWORD, including COM `this`. The service returns HRESULT and writes mapped output pointers. This is a platform COM boundary, not an implementation of Direct3D itself. No device is invoked during reconstruction tests. Arbitrary user-installed replacement vtables, exception unwinding and corrupted/unmapped pointer states are outside the proven original-class runtime domain.

Evidence is actual11405/11411/11470/11472/11474/11476, original vtables11419/11477, actual13036/13038/13040/13044/13046/13050/13052 and original13041/13042/13047. `verify-renderer-texture-creation-instructions.mjs` passes500 fixtures across nine entries:4,500calls,753 reached instructions,641,650steps, all mapped bytes>=10000h and exact ordered COM requests. It covers success/failure, both surface-sharing paths, populated binding cache, kinds/modes/formats, negative/overflow dimensions and dimension-pointer aliases. Eight focused tests cover the concrete arithmetic, alias, ownership and release cases. Actual producer→viewport and full parent checks are documented in [race viewports](race-viewports.md).
