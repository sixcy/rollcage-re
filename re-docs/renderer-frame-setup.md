# Renderer frame-clear and viewport producers

`src/renderer-frame-setup.mjs` reconstructs actual frame-clear parent `529030`, target-policy helper `528fe0`, and viewport/cache/float-matrix producer `511380`. Evidence is retained in native-simulation 13244/13245, 13365–13368 and original float/vtable tables 11419, 13427–13429. Redux SHA-256: `c0582271862ec373f00d01545c2a95aef0abb10a32513ec585271d08b10c6cf5`.

`hasRendererConfiguredTargets(manager,runtime)` requires settings byte `+63 == 1` and a positive signed manager `+51c`. It scans four 24-byte settings entries, requesting the live singleton each iteration, and returns true when the entry's enable byte and raw target DWORD are both nonzero. `529030` discards that return but still executes its real singleton calls/state changes whenever the captured skip byte is zero.

`setRendererViewport(manager,rectangle,runtime)` captures the 16-byte input vector, writes manager's cached rectangle at `+4ec`, and only then reloads the individual input DWORDs into its D3D viewport local. Overlapping inputs can consequently produce different cached and submitted rectangles. Direct3D `SetViewport` receives that actual mutable local. The four post-COM DWORDs convert as unsigned values to float32; a CRT memset clears the 64-byte matrix before its scalar float stores. Width/height scaling and translation reread the live float fields afterward, preserving both COM- and memset-side changes. Every arithmetic step retains scalar SSE precision.

`clearRendererFrame(manager,flags,color,skipViewport,runtime)` captures the skip argument's low byte before callbacks. It calls actual `TestCooperativeLevel`, then reloads the caller's flags. Stencil clearing requires manager byte `+52e` to equal one. Nonempty clears optionally invoke the original viewport virtual target `511380`, reload the live device/color, and call `Clear` with depth bits `3f800000`. Cooperative-level and clear failures retain the original AL success return; the source does not invent renderer recovery.

`tools/verify-renderer-frame-setup-instructions.mjs` passes **6,000 calls, 309 reached instructions and 592,715 steps** in 1,200 fixture worlds. It compares every mapped byte at and above `10000h`, defined returns, exact CRT/Direct3D requests including COM child ESPs, and FS restoration. It reaches 2,869 actual viewport producers, 3,600 clears, 3,200 target-policy helpers and 166 lazy settings constructors. Cases cover unsigned boundaries, overlapping vector input, mutable COM viewport storage, changed caller flags/color/device, memset-side float changes and persistent clear/viewport sequences. Five focused tests preserve these rules.

CRT/Direct3D/critical-section operations are explicit services. The original executable and graphics device are not run. [Present/statistics `5290c0`](renderer-frame-presentation.md) now has a separate actual clock/command/present proof with four persistent clear→present frames. Material/shader creation, full `510080`, bootstrap and teardown remain separate work; these packages do not claim a complete rendering loop.
