# Renderer startup storage

`src/renderer-startup-storage.mjs` reconstructs draw-queue initializer `51de80`, worker-state constructor `530480`, its sentinel allocation `530da0`, two `530320` blocks and their `530380` mutex/event objects. Retained assembly is native-simulation 13069/13070, 13071/13072, 13103/13104, 13133/13134 and 13162/13163. The actual compiler array-construction helper `5688c0` and its SEH prolog/epilog are also executed by the native checker. Target: Redux SHA-256 `c0582271862ec373f00d01545c2a95aef0abb10a32513ec585271d08b10c6cf5`.

`initializeRendererDrawQueue(queue, capacity, records, kind, unused, runtime)` keeps the four-argument native ABI. It stores capacity at `+1c`, record count at `+18` and kind at `+14`; the final argument is unread. Record storage requests `records * 24` bytes through array-new, selecting `ffffffff` on unsigned multiplication overflow. The two DWORD-array malloc requests independently reload the live capacity and use wrapped `capacity*4+4`. Each failed malloc reaches the real game assertion policy; a retry response has its own native breakpoint address. Initialization performs all three original memsets: first array `(capacity+1)*4`, second array `(capacity+1)*4`, then the second array again `capacity*4`. Each rereads the capacity/root at the native point. The final root is loaded before clearing `+20/+24` and writing its first DWORD. Record-array bytes and object padding are not invented as zero.

`constructRendererWorkerState(worker, runtime)` initializes only the original fields and retains inactive gaps. Its `414h`-byte tree sentinel initializes three self-links and the two tag bytes, preserving all other bytes. Two `50h` blocks each construct an actual game lock object, producing two mutex handles and two manual-reset, initially signaled event handles. Null platform handles are retained without a made-up failure branch. The source preserves the compiler constructor's native child ESPs for both blocks and the nested Win32 calls; it does not start worker threads.

`tools/verify-renderer-startup-storage-instructions.mjs` passes **4,500 calls, 304 reached instructions and 396,803 steps** across 900 fixture worlds. It compares all mapped bytes at and above `10000h`, defined returns, ordered CRT/Win32 requests including Win32 child ESPs, and restored FS linkage. Cases include live callback capacity/root changes, first/second malloc failures with the real busy assertion gate, wrapped capacity and overflowed record-size arithmetic, null handles, and preserved incoming bytes. Five focused tests cover these rules. CRT allocation/memset/exception handling and Win32 handle creation remain explicit services. No game function is mocked, and no original process, thread or platform object is executed.

This is storage/constructor closure. The containing `51e320` startup still calls the full renderer device initializer `510080`; broader window, material/shader and renderer lifecycle work remains separate.
