# Projectile launch producer

`src/projectile-launch.mjs` reconstructs `activateGroundProjectile` (`44af00`), `activateHomingProjectile` (`46b160`), and `activateSatelliteProjectiles` (`42feb0`). Their interface is `(record, localMode, unusedArg0, receivedPacket, transportContext, runtime)` with raw shared memory and native entry ESP in `runtime.scratchBase`; each returns native boolean EAX. Local mode produces the actual96-byte packet; received mode validates its type byte. Slot selection, owner and target identities, authored model locks, signed orientation, momentum scaling, position offset, random corrections, spatial/shapes insertion, trail reset, queued animation light and guarded `4710f0` packet feedback use actual recovered game algorithms.

`writeProjectileLaunchPacket` preserves each native MOVQ/MOVDQU block capture separately, including overlap with subsequent packet fields. The original projectile configuration uses mass `08000000h` and inverse mass `00200000h`; caller owner inverse masses are declared native-scale values rather than normalized guesses. The four-slot homing pool comes from actual `46a420`, including its common body/material/render/wormhole descendants.

The default connected oracle preserves private stack history from constructor through activation and later ticks. `42871f` writes a spatial row-map pointer into the activation caller frame minus eight, whose high word subsequently reaches a partially initialized trail-transform DWORD. Merely supplying the lookup result and outside flag was insufficient; the source now publishes this exact reached producer. Queued light payload fields also retain actual constructor/activation stack bytes. The compiler exception chain is explicitly synthetic (`FS:[0]=0`) and must be restored after every interpreted entry.
