# Autonomous opponent candidate generation

`src/autonomous-opponent-candidates.mjs` reconstructs the complete Redux `492d80` opponent-perception pass and its three reached policy branches: `4938f0` collision penalties, `493610` avoidance insertion, and `493290` follow insertion. The numerical closure includes `4919d0` route curvature, `493b00` linked-route side search, `493eb0` segment side measurement, existing actual route walkers/direction/nearest-point references, and the fixed-point root, division, cross, dot, and vector-scaling primitives. The small matrix-axis readers `4914e0`/`491510` and scaling helper `492030` are evaluated directly from their retained arithmetic. There are no required game-owned callbacks.

The main API is `updateAutonomousOpponentCandidates(body, lowestFreeAddress, {memory,scratchBase,handlers={}})`. Memory contains caller-owned native-addressed bodies,780-byte registry records at `909300`, session `5ecb1c`, route resource `90b98c`, candidate rows `91f1e0`, and special-point storage. `scratchBase` denotes native entry ESP. `initializeAutonomousOpponentTables(memory)` installs the original eight aggression thresholds at `570580`. It does not construct model/body/session/progression state. Optional `scoreCollision4938f0`, `appendAvoidance493610`, and `appendFollow493290` handlers replace individual branches for explicit boundary experiments; production defaults execute all three actual references.

The pass captures the model radius, aggression-profile selector and unsigned16 threshold, resets special-point count `6e650f`, derives whether human mode8 opponents are included, and scans the registry with a live session/count reload between cars. It rejects coarse distances beyond2000 units, computes forward displacement and projected closing time, and applies policy bits or per-opponent aggression words. It preserves strict speed, progression, time, mode, and side-state thresholds. The profile selector is captured before clearing the special counter; these bytes can alias, and that ordering is independently checked.

Collision scoring visits all twenty candidate rows, applies a lane penalty for the opponent's progression group, and uses normalized relative trajectory/cross distance for the proximity penalty. Both interpolation products use low signed32 arithmetic before integer division. Disabled/zero-group rows are skipped. The signed integer cross-distance metric uses all three components.

Avoidance creates special type1 rows. The lateral branch projects the body's actual side axis, choosing its sign from relative position and velocity; the lead branch advances the opponent velocity by a time-dependent shift. Follow logic updates local route points, measures both route curvatures, and searches linked groups for a side change. A successful follow produces special type2 rows; its separate fallback adds14 to enabled candidates on the opponent's progression group. Insertion updates the native special point pool at `91f600`, per-point byte `91f1c0`, row score/type/index, and live lowest-free index in native order.

`measureAutonomousRouteCurvature(group,index,positionOut,beforeOut,afterOut,{memory,scratchBase})` is exported for other policy consumers. It selects up to two points before/after the current point, normalizes both directions, then sums low32 squared cross components shifted by16, using crossY's sign. Endpoint failure returns0 and leaves output vectors stale. `hasAutonomousRouteSideChange` exports the actual twenty-slot global ring traversal, including its64-word visited list, queue wrap/full tests, packed link extraction, and comparison of side bit27. `measureAutonomousRouteSide` exports the exact segment selection and XZ determinant. These are byte-memory references rather than object identity substitutes.

All refer to the read-only installed Redux artifact. Compiler `568162`/`5684da` are ABI checks, not unported game behavior.

Validation:

- `node --test tests/autonomous-opponent-candidates.test.mjs`: ten focused tests pass, including real type1/type2 insertion, fallback score selection, strict distance rejection, endpoint output preservation, curvature sign, and the profile/counter memory alias.
- `node tools/verify-autonomous-opponent-candidates-instructions.mjs`:2,566 retained instructions;1,800 fixtures execute each of seven entries, plus40 complete parent alias fixtures. All12,640 calls match across44,870,437 interpreted steps. The report is `analysis/autonomous-opponent-candidates-instruction-check.json`.
- Full-parent calls reach53 collision passes,360 avoidance branches, and206 follow branches. The fixture corpus also exercises1,118 type1 and627 type2 insertions,32 linked route groups with ring wrap, both avoidance prediction branches, and a live candidate-score/relative-vector alias. Those counts describe exercised behavior rather than game-wide coverage.
- Comparisons include two complete16,384-byte bodies, registry backing bytes, model/session/progression/routes, candidate/special-point tables and neighboring bytes, side-search global arrays/cursors, output vectors, native scalar returns, and independently retained threshold bytes. The only admitted native boundaries check security-cookie equality or fail on the unreachable compiler range trap.

These are synthetic fixtures and retained-instruction comparisons. They do not execute the original process, infer missing upstream runtime producers, or prove a complete autonomous race. Native ABI stack is separate from game-owned structures; caller-supplied scratch preserves meaningful retained locals, while arbitrary saved-register stack garbage is not a public state contract. Fixtures keep integer-root and signed-division inputs in successful native arithmetic domains. Aggression-word producers, runtime model/progression construction, and broader candidate scoring remain the responsibility of their respective modules.
