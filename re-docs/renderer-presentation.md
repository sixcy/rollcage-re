# Renderer presentation parameters

`src/renderer-presentation.mjs` implements actual `5120e0`, the raw WindowsApplication getter `402aa0` and settings writer `4068d0`. The latter two are actual reached game helpers, not platform substitutes. `initializeRendererPresentationConstants` maps original fallback format preferences, bit-depth/depth tables and the original floating-point1 constant.

Presentation builds the original56-byte D3DPRESENT_PARAMETERS records at manager+378h, after applying actual getter50f1a0's capability tier and raw adapter caps. It preserves the initial settings-byte capture, live fullscreen/vsync reads, signed wrap in refresh differences, native one/half/third refresh matching, multisample enumeration2..16 with at most four supported results, target/depth format fallbacks at+500h/+504h and duplicated extra-window records. The number of windows at+374h stays live; each extra handle reloads the singleton and performs real CRT WindowsApplication RTTI.

`402aa0` targets descriptor6e2054, unlike Application getter402d10's6e20a4. It runs actual403430 lazy construction and publishes the static application before the RTTI service. `4068d0` writes width/height/depth/refresh, truncates its fullscreen byte and preserves scalar SSE conversion/division order for aspect/projection values. None of these helpers creates a host window or device.

APIs are `configureRendererPresentation(manager,runtime)`, `getRendererWindowApplication(runtime)` and `configureRendererGraphicsMode(settings,width,height,bits,refresh,fullscreen,scale,runtime)` using shared raw memory/native entry ESP. Genuine CRT allocation/free/atexit/RTTI and Direct3D COM queries remain services. Existing settings and debugger singletons are declared inputs of the current connected proof; the existing actual graphics-settings module supplies their settings constructor separately.
