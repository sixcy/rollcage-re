# Raw scripted motion and authored light bodies

`src/raw-scripted-motion.mjs` supplies `stepRawScriptedMotion(bodyAddress, runtime)` for native `0x476550`. Runtime carries `{memory, scratchBase, roundingMode, handlers?, maxOpcodes?}`; `scratchBase` is native entry ESP, and `roundingMode` is the explicit x87 conversion policy used when opcode7 normalizes a direction. Native script pointer `body+0x134`, wrapping offset word `+0x138`, timer words `+0x13a/+0x13c`, segment byte `+0x13e`, spawn byte `+0x13f`, and auxiliary-pack pointer `0x90b990` remain live mutable memory. The maximum-opcode count is a workflow guard, not a game instruction. The structured numerical reference `scripted-motion.mjs` remains unchanged.

The raw VM reloads `body+0x134` at every opcode, even after spatial or effect calls. Velocity opcodes capture their source words before overlapping velocity stores. Teleport and spawn commands read and store coordinates in native forward order, which can propagate values when bytecode/spawn storage overlaps the body. Teleport tests the insertion flag after removal and before position stores. Segment rollover increments the live byte and performs native dword timer writes at `+0x13a`, clearing both adjacent words. Momentum captures mass once and reads/stores each velocity lane in order. Opcode7 writes orientation in native column order, and the real length/normalization paths retain shared root globals `0x91d45c/0x91d460`.

Spatial removal `0x474850` and insertion `0x474600` are actual raw defaults from `body-retirement.mjs` and `raw-body-construction.mjs`, including packed body IDs, bucket heads and native `0x4286e0/0x4746f0` selection. The VM returns `{released, executedOpcodes}`; a release also reports `releaseResult`. Release is not unregistering or freeing the body.

`releaseRawScriptedBody(body, runtime)` reconstructs `0x46e4e0`. Its scripted branch changes flags/integration state, constructs the actual `0x41e3f0` quaternion, updates RNG `0x5ec954`, writes torque in X/Z/Y order, and emits16 pieces through actual `0x46e600`. Its other branch calls actual `0x435ba0` and then installs pointer `0x46e470` at `body+0x148`. That later callback is now implemented in [scripted-collision-filter.mjs](../src/scripted-collision-filter.mjs); a separate120-chain comparison follows actual release through474b20 event filtering and debris. This VM checker itself does not execute the callback. Optional handler overrides `call474850`, `call474600`, `call46e600`, `call46e4e0` and `call435ba0` preserve explicit boundary probes; ordinary defaults do not require them. Existing raw effect code may require genuine audio/library services when an actual populated sound bank reaches them.

`emitScriptedReleaseDebris(body, count, runtime)` implements complete `0x46e600`. It captures pose with Y minus `0x1e0000` and half velocity before emission, advances RNG `0x5ec958` twice for every positive requested count even when free storage is exhausted, consumes unsigned-word free IDs into the active table, and writes128-byte debris records with life15. Spatial insertion precedes kind/color/velocity fields. Free cursor `0x902b8c` commits at the end; active count `0x902b88` commits per piece. The original comparison of a widened unsigned-word ID against `-1` can never match; the source preserves that behavior rather than inventing a `0xffff` sentinel. General arbitrary stack/global/body overlap is not established by these checks; the meaningful body/script/spawn and spatial/script aliases below are explicitly exercised.

## Authored producer and light integration

`dynamic-light-state.mjs` now binds this raw VM as the default `0x476550` call. Actual authored constructor `0x44e220` consumes32-byte light rows, script offsets from `0x9092b4`, palettes from `0x9092ac`, spawn positions from runtime pack `0x90b990+0xa8`, and384-byte arena claims. It initializes storage to FF and writes only explicit fields. In particular mass `+0xa8` remains `0xffffffff`, and rotation is initially stale. The connected check preserves those bytes. Its release script first executes opcode7 to establish a valid forward direction; immediately releasing the initial FF direction would produce a zero fixed-point length and native division fault, which is not hidden by an invented orientation.

Light updater `0x44d960` invokes the raw VM, then adds raw velocity into position, moves/re-registers the light and reloads the pool count. A release does not remove the light's body pointer, so subsequent updates can reach the unscripted release effect branch again. The connected comparison checks this actual behavior.

The loaded script/palette/spawn tables, terrain buckets/segments, body arena, effect pools and sound bank are explicit inputs. Their broader original loader/lifecycle provenance is not claimed by synthetic runtime construction. The connected producer is the actual game-owned `0x44e220`, rather than a fixture filling assumed mini-body fields. Original-process execution has not been performed.
