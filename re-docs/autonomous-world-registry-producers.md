# Autonomous world inputs and native fragment producers

The36 rows reached through `849a5c` are a spawned world/fragment-body pool. They are **separate from the six participant records at `909300`**. `480760` constructs36 bodies in three model/configuration groups; `480bf0` activates available bodies; `480e90` ages, retires and splits them. The nearby-object consumer `411e70` reads these raw rows. Describing synthetic nearby fixtures as traffic does not establish that the registry owns participant vehicles.

`src/world-fragment-registry.mjs` reconstructs these three complete functions. `src/raw-body-construction.mjs` supplies their actual object/model-storage, initialization, physical spatial insertion and collision-shape registration children. Existing checked retirement/effect modules supply physical removal and effect descendants; source imports those implementations instead of duplicating them. Installed files remain read-only, and these checks do not execute the original process.

## Fragment construction and storage

`initializeWorldFragments({memory,scratchBase,allocate})` is `480760`. `scratchBase` denotes native entryESP; `allocate(size)` is the ordinary CRTmalloc service and must return mapped addresses. The native successful-allocation path allocates288 bytes for36 eight-byte registry rows,672 auxiliary bytes, and8192 workspace bytes. It resets cursor `6e6bcc`, another counter `6e6bd0`, and bytes `9207e0/9205d8/9207e1`. After constructing bodies it clears the registry and auxiliary blocks again, then publishes four workspace partitions at auxiliary `+8c/+134/+1dc/+284` with2048-byte spacing. There is no invented allocation-failure recovery: subsequent native stores require readable mapped allocations.

Bodies are preallocated through `4741c0(model,1c07,180,0)` and `4798d0`, then immediately removed from their physical spatial lists through `474850`. Availability bytes are `849940[index]`; body pointers are `849980[index*4]`. Model pointers come from current pack `90b98c`, model table `pack+18`, and signed16 model indices through `pack+58`: offset6 for slots0..3, offset4 for4..11, and offset2 for12..35. Configuration addresses respectively are `5ecc00`, `5eccd8`, and `5ecb28`. `initializeWorldFragmentTemplates(memory)` copies retained executable bytes from `src/world-fragment-templates.json`; the560-byte range is evidence788, not synthetic tuning.

## Activation and maintenance

`activateWorldFragment(position,momentum,selector,tag,{memory})` is `480bf0`. `position` and `momentum` are pointers to signed32 XYZ. Momentum is copied with a wrapping left shift8. Selector0 searches availability slots12..27; selector1 starts4..11 then falls back to12..27; selectors2/3 start0..3 then fall back through both smaller groups. Successful classes are3/2/1. Selectors outside0..3 and exhausted availability return without advancing the cursor.

The registry row is captured once using the incoming cursor. **When that row is occupied, native code checks the same row28 times while advancing and wrapping the cursor; it does not search other registry rows.** The resulting cursor returns to its original ordinary0..27 value. This behavior is preserved rather than repaired. A successful activation publishes age64, availability, slot/class, callback4810b0, row backpointer `body+164`, low-byte tag, three radius-derived descriptors, four shape rows, and physical spatial membership. It then advances the live cursor once. Initializer and maintenance cover36 rows, but this activator only selects28 slots; the producer/use of the remaining eight active rows is not established by this function.

`recordWorldFragmentImpact(body,other,{memory})` is the installed4810b0 collision callback. With a nonzero other body it reads signed16 velocity high words at6a/6e/72 from both bodies, computes three wrapping32 squared differences, and stores only low16 of their sum at `body+160`. A zero other pointer leaves the previous measure unchanged. It returns1. This field is a wrapped squared-relative-speed impact measure, not an age counter.

`maintainWorldFragments({memory,scratchBase,soundRuntime})` is `480e90`. It scans36 live rows in ascending order, counts initially active rows in `6e6bc8`, changes low body type bits based on the incoming age62 cutoff, and decrements nonzero age when the low clock byte at90a548 is divisible by64. The impact measure at `body+160` is compared unsigned against700/1000/1200 for class1/2/other. Surviving rows reset that measure. Expired or threshold-reaching rows release shapes and spatial membership, free their availability slot, clear active age, emit actual sound event17 plus particle/debris effects, and split classes greater than1 into two smaller fragments at X/Z offsets±300000. Newly activated later rows are visited in the same scan. The count is visits to active rows, not the final number of active fragments.

Sound dispatch defaults to the recovered484bb0→40ea40 path; `soundRuntime` supplies its existing libaudio/CRT services when a populated bank reaches them. The connected producer comparison uses an empty sound bank and follows the actual native early-return guard. It still executes actual particle/debris allocation, RNG, spatial insertion and splitting. The separately checked sound dispatcher covers populated-bank behavior.

## Obstacle registry and polygon subset

The obstacle registry is distinct: unsigned count `6e6514`,12-byte rows at `920b40`, pointer at+0, selected polygon count+4, selected pointer range+8. Retained xrefs identify `44c2b0` as its direct writer; `47ea40` calls this resource loader before initializing fragments. After game helper48ab50 returns, loader instructions44cf99..44cfb7 append the object only when byte `object+19a` is zero, preserving the row's other eight bytes, then increment the count. `appendLoadedWorldObstacle(object,{memory})` ports **only this loader segment**; full44c2b0 and48ab50 are not thereby claimed reconstructed. No capacity guard is present in the segment.

`buildAutonomousObstaclePolygons({memory})` is complete4123a0. It captures the obstacle count, resets shared count6e6520, and publishes up to60 polygon descriptor pointers at6f95a0 across all objects. Even empty/rejected objects publish the current pool pointer and zero local count. For each object it finds the maximum signed16 Y among transformed8-byte vertices; a negative maximum rejects all polygons. Otherwise a face needs a nonzero packed8-bit vertex ID whose Y is **strictly greater** than maximum-24. Metadata low nibble4 excludes a polygon. Packed face records stride8; four IDs occupy its first dword. Authored polygon descriptors stride20 and supply face-start/end bytes8/9. One matching corner admits a descriptor once. Rejected/tail pool bytes remain unchanged.

Evidence791 shows the initial mapped bytes around6e6514 are zero. The complete direct xref set does not show an explicit reset store: only consumer reads and the loader increment. A later reset through indirect/wider memory initialization is not established. The reference consequently does not invent a reset or assume repeated loader calls begin at zero.
