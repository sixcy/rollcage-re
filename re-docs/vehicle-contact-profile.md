# Vehicle contact profile initialization

`src/vehicle-contact-profile.mjs` reconstructs the whole `41ebb0` initializer from retained `1878-contact-profile-initializer.json` and `1879-contact-profile-initializer-assembly.json`. `initializeVehicleContactProfile(body, {memory})` reads the session pointer at `5ecb1c`, the body's unsigned-short identifier at `+65e`, and the profile byte at `session + identifier + 1c`. The profile selects an eight-byte row starting at `5eadd4`. Native does not validate the profile index: callers supply readable address space, and the reference preserves that addressing rather than imposing the seven authored rows as a runtime limit.

The initializer publishes the recovery-table pointer at `91f6a0`, then replaces ten three-bit lanes of body `+6f4` and eight lanes of `+6f8`. The high two and high eight bits respectively survive. Each lane has its original separate DWORD write, and the source table word is reloaded between lanes. Difficulty and the selected profile address are captured before publication; the mode at `920f84` is read later, after earlier policy writes. These details matter when body, profile, session or globals alias.

Difficulty zero selects table `5eae14`. It reduces primary-word lanes at shifts `3,6,9,18,21,24,27` by `3,2,2,2,1,3,2`, and secondary-word lanes at shifts `0,3,6,12` by `3,2,2,3`, saturating at zero. Secondary shift18 rises by three with a ceiling of six. Secondary shift21 rises by three for mode zero, by one for mode one, and by zero for every other unsigned mode, also with a ceiling of six. Difficulty two selects table `5eae0c`, raises secondary shift9 by two below three and by one from three through six, and replaces primary shift3 with six when its original lane is at most three, otherwise seven. Other difficulty values copy the selected profile without these adjustments and use `5eae0c`.

`initializeVehicleContactProfileTables(memory)` separately restores the seven original packed rows and the two eight-byte duration tables. This is static-data restoration, not an invented native initialization function. `src/vehicle-contact-profile-tables.json` retains the exact 72 copied bytes, source target SHA, retained read Evidence and content SHA. The nonzero-difficulty duration table is `[45,40,35,30,25,20,10,4]`; the zero-difficulty table is `[45,40,35,30,25,20,15,5]`. Retained `2340-vehicle-contact-profile-words.json` also includes the following eight bytes for provenance; those neighbors are not written by this restoration. The mode jump-table bytes are retained under `2341`.

`node tools/verify-vehicle-contact-profile-instructions.mjs` passes 4,000 initializer cases, including 3,466 alias cases, plus 1,200 actual initializer-to-`41f380` recovery chains and 240 initializer-to-`41e080` collision-callback chains. It compares every mapped byte at or above `10000h` after each operation and the exact ordered stores of the initializer and direct recovery calls. Private stack storage is excluded. The report records 118,799 compared stores, 849,301 interpreted instructions and 686 reached instruction addresses. The callback chains run the actual score and recovery functions with legitimate sound/debris gates; the compiler-cookie service is their sole external callback. These are synthetic supplied runtime fixtures interpreted against retained instructions, not original-process execution. The report is `analysis/vehicle-contact-profile-instruction-check.json`.

`node --test tests/vehicle-contact-profile.test.mjs tests/vehicle-collision-filter.test.mjs` passes all 16 tests, including six new tests for the original bytes, all copied lanes, difficulty/mode boundaries, a live mode/body alias and actual recovery using the produced table pointer. Recovery retains its separate random stream `5ea4d4`; initializing a profile does not seed or advance it.

## Upstream producer boundary

Retained `2342` identifies caller `410060`; `2344`/`2345` retain its pseudocode and full assembly, and `2343` retains seed references. Its once-only branch copies the DWORD at `session + 618` into `5ea4d4`. Difficulty `5ea4d8` becomes two if session byte `58c` is one or session byte `551` is one of `2,4,6,7`; otherwise it comes from session byte `585`. The same branch produces mode `920f84` from session byte `579`: below three gives zero, three through five gives one, six through nine gives two, and above nine gives three. It also reaches `4123a0`, `420270` and `491ee0`, then sets the `6e650d` initialization guard. Later body setup calls `41ebb0` at `4101f7` before tail-calling scheduled planner `41f900`.

This package closes the profile initializer and its actual contact-recovery consumers. It does not reconstruct the whole `410060` constructor, its session-field producers, body registry construction or every constructor callee. Seed, difficulty, mode, body address and session storage remain explicit upstream runtime inputs until that constructor is integrated. Installed executable/data files were read only and no original process was run.
