# Satellite projectiles and terrain control

`src/projectile-satellites.mjs` contains full `42f950` satellite ticks, shared `42fce0` master state, and actual `430780` two-ray terrain control. Each receives raw addresses and `{memory,views,grid,scratchBase,roundingMode}` with native entry ESP. `updateSatelliteMaster` gates on master+190 against the live frame clock. All three satellites therefore share one timer/phase/radius update per clock. Phase adds16 then clears its high byte; radius uses signed16 comparison and clamps to128 only after subtracting10. Horizontal damping uses the native separate arithmetic shifts and signed overflow tests.

`430780` calls actual `queryRawTerrain`/`424ff0` twice using one output slot: the first height/hit flag are captured before the second ray shifts X/Z by half velocity. Four hit combinations select the exact vertical momentum adjustment. No supplied terrain answer is accepted.

`42f950` copies master state into the satellite, updates a live three-member matrix table, derives orbit phase from the satellite index and master phase, builds packed transform scratch, moves/re-registers the satellite spatially, and calls actual trail generation. Its partially initialized packed scratch DWORD is retained. State16 drains all three trails and decrements the shared active-byte count only when every satellite is inactive. Unsupported master states follow the native position-copy path, while state0 returns after state/timer copying.
