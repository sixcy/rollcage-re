# Projectile route search and endpoint transitions

`src/projectile-routes.mjs` implements `findProjectileParticipantRoute` (`44b970`) and `updateProjectileRoute` (`44bc30`). Both take a raw body address and `{memory,scratchBase}` with actual native entry ESP. Inputs are runtime route groups, authored16-byte points/packed links, the two-DWORD adjacency table at runtime pack+94, participant records, and body route fields `6bc`/`6cc`–`6da`.

The search selects the first participant whose record+1d equals1, or the first record beyond the scanned count if none matches. It writes body+198 before comparing group identities. Same-group EAX comes from participant+58 and leaves the queued path stale. Different-group searches publish the destination byte in body+6da, then search with an eight-entry path limit. Successful graph searches still return **-1**; success is expressed through the written path and `FF` terminator. Visited bits persist between depth attempts, preserving native pruning behavior even when that prevents finding a graph-theoretically reachable destination. The source retains that behavior rather than replacing it with a generic shortest-path algorithm.

The endpoint update compares wrapped signed32 squared distances, uses signed16 point indices and directions, follows both packed route links in native order, shifts the queued path, and handles reversal, open endpoint bounce, and closed-group wrap. Its mode-dependent proximity test reads the live target body at+198. It returns1 only for that early proximity exit; ordinary route progress returns0. Group+5 is identity/progression metadata, while group+2 controls reversal and group+4 controls wrapping.
