# Auxiliary input and preset chat

`src/vehicle-auxiliary-input.mjs` reconstructs the complete `42be80` per-record auxiliary input stage and its reached preset-message path. The public entry is `updateVehicleAuxiliaryInput(recordAddress, {memory, scratchBase, handlers})`; `scratchBase` is native entry ESP. `initializeVehicleAuxiliaryInputTables(memory)` installs the original three-byte `": \0"` separator at `5d049c` without resetting caller-owned settings, participant, network or address state.

The parent captures `(*record)+714` once. It acts only on `909300 + selected*30c`, where selection `6e9f70 == -1` maps to zero. When `6eafe0&1` is set, bits20 through29 dispatch preset IDs0 through9 in ascending order. Bit30 toggles the byte at the live settings pointer `(*5ecefc)+25`; bit31 toggles `91ce90&4`. These local toggles work independently of the network gate. The captured flags remain authoritative if an external send callback changes the body, record, selection or flags.

`sendAuxiliaryPresetMessage(id, runtime)` implements `42bdb0`. It skips an empty preset at `settings+dce+id*64`; otherwise it builds `settings+120`, the original separator and the preset in the native stack buffer. It preserves the actual forward copy order, including four-byte chunks and the remaining byte count. Message composition precedes the recovered `4a0620` queue's64-byte truncation. The queue shifts the four65-byte history rows and, when `6eafe0&4`, invokes the existing actual `4a0420` transport parent.

The auxiliary caller always supplies mode2 and flags0. Its complete reached transport path is actual: readiness `471820`, checksum `4a0180`, address constructor `49ea00` and its `54d660/54d700/54d720` helpers. `471820` preserves ECX/EDX, so the peer fanout, mode1 and local-delivery branches of `4a0420` are unreachable from this caller. Their existing explicit boundaries are not presented as recovered by this module. The transport helper exports are `sendAuxiliaryNotificationPacket(packet, length, runtime)`, `isNotificationTransportReady(runtime)`, `checksumNotificationPacket(packet, signedLength, runtime)` and `constructNotificationAddress(destination, valuesAddress, runtime)`.

The checksum zeroes packet+4 before summing unsigned bytes with signed length comparisons and wrapping integer additions. Address construction first initializes its default ten-byte address and socket-shaped storage, then reloads the supplied address fields and copies the live20-byte template at `6f2424`. Retained default bytes are tenFF bytes at `5e8280` and twenty zero bytes at `6f2424`; these globals remain caller-owned and are not reset by the table initializer. Direct tests preserve aliases when address input overlaps the destination.

## Service and producer boundaries

Only the reached platform network interface is required by the source: `handlers.sendInterface({memory, ecx, functionAddress, args, address, addressFlags})`. Its integer or `{eax}` return is interpreted by the existing transport parent. The five integer arguments are packet pointer, length, two transport flags and zero; the separate native40-byte by-value address has trailing flags `[1,0]`. This is a data/service contract; the source opens no sockets and sends no traffic.

The native address constructor initializes bytes0..9 and16..35. Bytes10..15 and36..39 retain stack padding; the checker compares every initialized field and explicitly excludes that unspecified residue. Native and JavaScript packet addresses and initialized address bytes agree. The scratch adapter maps the existing transport's separate values/address scratch areas back to the exact native frame addresses.

Runtime producers remain explicit: selected-player state, body edge flags, settings/player name/preset storage, participant rows, interface objects and the address globals. The recovered code retains the native fixed128-byte message buffer and assumes valid NUL-terminated authored/name strings that fit before queue truncation. It does not establish constructors, malformed-string handling or a safety bound absent from the native parent. Compiler stack allocation and security-cookie checks are interpreted through compiler-service adapters; no original executable is launched.
