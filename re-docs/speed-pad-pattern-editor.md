# Complete speed-pad arrow patterns

`src/speed-pad-patterns.mjs` recognizes complete2×2 original category-1 arrows from complementary mirrored tile pairs, checking both quality variants. It does not assume that page20 always contains arrows. The current palette retains all four cropped tiles; tracks without a recognized complete pattern retain the ordinary surface brush. `speedPadTilePairs` preserves the original two-cell recognition for older saved commands.

The Surfaces tool offers Single tiles / brush and Complete speed-pad arrows. Current arrow mode previews a four-cell footprint, supports quarter turns, and adds one atomic terrain-history command. Every destination cell must fit inside one nonanimated sector with collision coverage, including generated road sectors; a failed footprint changes neither quality. Painting ordinary tiles over an existing arrow removes the overlapping arrow command as a whole.

Geometry corners and UV packet corners differ when vertex flag4 is clear (489e40). The compiler converts source UVs into physical TL/TR/BL/BR order, rotates the footprint and UV corners, and converts back using each destination cell's mapping. It copies the full16-byte descriptor, preserving page/CLUT/material fields. An appended UV table preserves all existing relative references and shared descriptors; grid topology, collision normals and coverage stay unchanged.

Actual acceleration is category1 in materialDWORD+12. Native48d680 uses the first matching wheel contact and adds3000h or5000h to body+6a8, depending on throttle bit40h. Page20 is an atlas, not the acceleration identifier. This behavior is distinct from the artwork.

Version5 projects save references `{sector,cell,sourceSector,sourceCell,rotation}` in `terrain.patterns`; those records remain two-cell placements when loaded or resaved. Version6 adds `kind:'arrow4'` only for new four-cell commands. Neither accepts caller-supplied UV bytes. When reopening a recognized editor export, TrackEditor reads original templates from the retained stock IMG prefix using the canonical verified IDX view. Starting archives still identify the project by their current resource hashes. Offline callers compiling an edited starting archive should provide each quality's `originalGeometry` from that retained canonical view.

Validation: `tests/speed-pad-patterns.test.mjs` covers mirrored recognition, physical corner/rotation mapping, atomic bounds and animation rejection. `analysis/speed-pad-patterns-matrix-20261025-v2.json` checks all40 original resources, all rotations, unchanged grid coverage and category1, with reconstructed races where paths exist. `analysis/speed-pad-browser-20261025-v1/report.json` records actual palette selection, hover footprint, real placement, undo/redo, project round-trip and stable Camera controls. The combined v5 matrix applies arrows alongside route, checkpoint and assembly changes. Dedicated native lifecycle reports separately establish actual contact and drive increments.
