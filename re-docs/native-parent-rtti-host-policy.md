# Scoped native parent CRT observer host policy

This implements the separately prepared `parentRttiObservation` contract from `tools/lib/native-parent-rtti-capture.mjs`. It observes the original CRT call, supplies no return value and performs no gameplay writes. No original game or executable fixture was launched during this implementation. The typed source adapter and retained instruction/import proof remain documented in `native-parent-rtti.md`; camera-only original-process evidence is retained separately. The mixed camera/weather extension below has only pure host validation at this checkpoint.

## Capability, selection and original checkpoints

`NativeDebugger.GetCapabilities()` declares implemented V1, optional graph V2 and optional mixed camera/weather V3 capabilities. An active profile records only its selected capabilities in the capture header's `helperCapabilities`, always including `scoped-parent-rtti-and-singleton-map-preflight-v1`. Existing profiles retain their prior header and execution path when the relevant option is absent.

C# validates the same frozen purpose policy, ordered15 sites, exact three startup observations/actions, security/window/document policy, target SHA256, one selected parent and map/CRT descriptor contracts as the JS profile. It retains the13 original observations and admits at most eight extra CRT snapshots, for21 total; duration90 seconds and one million debug events remain unchanged. It cannot combine held-force, controlled-settings, worker, pending-frame or legacy observation-activation policies. No extra startup/game writes are permitted.

Foreign-thread parent checkpoint hits are rejected before phase-predicate matching, parent latching or map reads, without advancing matching/snapshot counters. On the first selected owned-main450e50 entry, the host latches actual U/clock/iteration, incoming nonvolatile registers and original caller/iteration words. All ten original parent checkpoints must then follow in order with the actual derived child stack and unchanged parent identities. This preserves every checkpoint; no native observation is substituted for carried source state.

## Conditional singleton/map input observation

At selected parent-before, after-cameras and after-world-effects, a purpose-specific preflight runs before resolving any **snapshot** ranges. The existing phase predicate has already been read to select the configured skip/matching hit; records explicitly say so. The preflight is on the owned main thread within the same uncontinued debug event.

It observes DWORD at actual root RVA2efb38, requires nonzero APP, then observes DWORD at actual APP+7c and requires nonzero head. Bounds are checked before pointer addition. Null short-circuits before chasing; an unreadable nonnull pointer such as16 is a real read failure, never classified as null. The initial actual APP/head identities are latched and must be stable at both later points. There is no resume between this check and the following range resolution/read.

The separate fixed100-byte guarded head row and nonnull readable-region row capped at16 MiB retain their original meanings. This policy adds no generic guarded-pointer/readable-region combination, assumes no capacity from the region and provides no replacement map. Only original parent-entry coverage can supply source input; later map bytes remain observations for comparison.

### Opt-in bounded viewport map graph

`parentRttiObservation.viewportMapGraph` may explicitly enable `{maxNodes:8,maxKeyBytes:256,breakpointIds:['native-control-before','native-control-after-cameras','native-control-after-world-effects']}`. All values and the ordered checkpoint list are fixed; the existing 15 sites, 21-snapshot ceiling, 90-second/event limits and three startup actions remain identical. Absent this option, no graph reads, extra ranges, graph proof, or graph capability are added to V1 captures. `GetCapabilities()` advertises implemented V1 and V2 support; `GetCaptureCapabilities(options)` preserves the exact V1-only header without this option and adds `scoped-parent-rtti-viewport-map-graph-v2` only when enabled.

At each of the three map checkpoints, the graph read follows the successful singleton/head preflight and precedes configured snapshot range resolution within the same stopped owned-main-thread debug event. It observes the actual APP+7c eight-byte header (head/count) and actual sentinel's 16 bytes, then visits all non-nil nodes in deterministic root/left/right breadth-first order. Retained constructors `3687-weather-4061a0-procedure_assembly.json` and `3717-weather-405dd0-procedure_assembly.json` establish 100-byte node/head allocations; the separate graph sentinel row admits only its 16 structural bytes. Each ordinary node gets exactly 100 observed bytes. Nil child links must reference the observed head; null children, shared nodes, cycles, incorrect parent backlinks, count mismatches, incorrect sentinel minimum/maximum, unreadable storage and 32-bit overflow fail. Head color/nil bytes must be 1/1; ordinary node nil is 0 and its color is 0 or 1. This checks structural links and extents, without inventing source tree operations or requiring topology to remain unchanged between checkpoints.

Node key length is DWORD+32 and capacity is DWORD+36. Capacity below 16 selects the inline key at node+16; larger capacity selects its actual DWORD pointer. The observed key length must fit its capacity and require at most 256 bytes including NUL. Inline storage is retained in the 100-byte node, with no extra read. Heap keys receive a separate read of exactly length+1, never capacity bytes. The terminating byte must be observed zero. Zero-length keys still have an actual one-byte terminator; empty maps have no node/key reads or zero-byte fabricated rows. A nonnull unreadable pointer such as 16 is a read failure. At most 2,872 extra data bytes per checkpoint are possible (header8 + sentinel16 + eight nodes100 and heap keys256), without changing the existing transport domains or dropping any output.

Graph rows use `source:'parent-rtti-viewport-map-graph'` and `graphRole:'header'|'head'|'node'|'heap-key'`. Their IDs are `parent-rtti-map-graph-header`, `parent-rtti-map-graph-head`, `parent-rtti-map-node-i`, and heap-only `parent-rtti-map-key-i`. Node/key rows also retain `graphNodeIndex`, `graphPath` (`root`, `root.left`, etc.) and `nodeAddress`; every row has its actual address/length, blob and SHA256. The `parent-rtti-map-graph` marker is embedded unchanged as snapshot annotation `parentRttiViewportMapGraph`. Besides the common parent provenance, it records snapshot ordinal, APP/header/head/tree-root addresses, actual eight-/16-byte header/head hex, count, bounds, and BFS node metadata (parent/child addresses and key address/length/capacity/inline-or-heap/range identities). Inline `keyRangeId` is null. Flags explicitly state same stopped event, successful prior singleton preflight, complete graph observation and before original instruction. A graph failure produces a separate failure marker and aborts without a successful graph snapshot; completion additionally requires all three graph observations. No game state is written or reconstructed by this reader.

## Proof records

Each proof includes owned PID/TID, parent entry debug ordinal/U/clock/iteration/caller and its actual observed debug-event ordinal. Independent records are embedded unchanged in the relevant snapshot, including their emitted elapsed time:

| Record | Snapshot annotation | Meaning |
| --- | --- | --- |
| `parent-rtti-map-preflight` | `parentRttiMapPreflight` | Actual root/slot DWORDs, APP/head pointers, initial latch or stable identities, before-range/same-event proof |
| `parent-rtti-activation` | `parentRttiActivation` | Auxiliary bytes already closed, exactly two verified code patches, before snapshot publication/original instruction |
| `parent-rtti-admitted` | `parentRttiObservation` | Call/return role, pair index, raw hit, derived Q, exact52-byte stack, camera return, clock/singleton DWORDs and five arguments |
| `parent-rtti-closed` | `parentRttiClosure` | Actual pair/snapshot totals, closed window and no open call before camera range resolution |

Per-site `parent-rtti-breakpoint-activated` rows retain original full instruction bytes and patch identity. `parent-rtti-skipped` and `parent-rtti-checkpoint-skipped` explicitly retain counter-neutral exclusions. Failed map preflight is retained separately and aborts before the optional graph ranges. Completion's `parentRttiObservation` includes the ten checkpoints, three startup snapshots, pair/snapshot/preflight totals and closed/no-open state. The independent JS provenance verifier is owned separately and must check actual records before a future positive runtime claim.

## Pure validation and remaining limits

Eleven focused tests in `tests/native-parent-rtti-host-policy.test.mjs` cover the five V1 cases (typed validation plus28 independent profile/security/write mutations; lifecycle and max-four ordered pairs including capture/activation/publication order; null/unreadable/foreign/outside pointer admission and identity stability; exact opcode/counter guards and actual runtime source ordering; retained instruction proof plus positive NAME/MODE and negative swapped call, return and preliminary-reader guards), three graph cases and three mixed-weather cases. The graph cases include a synthetic three-node tree with a heap key, empty-map and exact256-byte key bounds, malformed/cyclic/overflow/missing-storage negatives, full typed opt-in validation with eight independent policy mutations, exact V1-header preservation, unchanged startup/sites/bounds, and runtime preflight/read/publication order. Mixed tests check retained caller instructions, valid camera→weather1→weather2→world lifecycle, failure on missing/reordered/cross-query pairs, changed caller/name/output/type/padding/clock/singleton guards, exact dynamic ranges, foreign-thread/no-read behavior and full typed policies with eight independent negatives. The swapped guards leave pair counters/open-call state unchanged. The prior reversed camera host ABI was corrected in both guard sites and the synthetic fixture; it supplied no native RTTI evidence. All host calls use `-NoProfile -Command` pure C# calls, hidden windows and timeouts. They execute no target code, create no device, modify no settings/security policy and launch no native fixture.

These tests and constructed JS adapter records establish the host contract, not a native CRT result or full parent match. Full wrapper private ABI/SEH, unsupported camera/weather callers, new allocations, map-node/service producers, broader renderer startup and general interleaving remain independent bounds. Original-process observation and semantic comparison require root's separately reviewed, announced capture and final verification.
