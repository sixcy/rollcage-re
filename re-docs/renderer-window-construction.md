# Renderer WindowsApplication setup

`src/renderer-window-construction.mjs` reconstructs `50d9a0` and the actual `50d750` class-registration and `50d840` window-creation algorithms. It binds the observed Application vtable's real `402e60` title, `402e70` icon and `402940` menu getters, and uses actual `405010` graphics settings. Unknown virtual targets are rejected. Evidence is retained in 11465/11466, 13357–13360, 13375–13380, original vtable 13113 and original strings 13389–13391. The stored literals are **Razor Engine Window Class** and **Rollcage Redux**; no window title was inferred from UI appearance. The PE import table was independently read from the SHA-verified installed executable to confirm the exact Win32 API names.

`registerRendererWindowClass(application,brush,runtime)` builds the original 48-byte `WNDCLASSEXW`, including game window procedure pointer `50d640`. Small unsigned brush identifiers at most 24 are incremented. Existing class information returns success immediately. Icon and cursor use the original application getters/resources, and fullscreen settings suppress the menu. `RegisterClassExW` success tests its low WORD, rather than the complete returned DWORD.

`createRendererWindows(application,unused,x,y,width,height,fullscreen,count,windowed,runtime)` preserves all eight raw arguments; the first is unread. Zero dimensions independently query system metrics even if the later fullscreen branch replaces both dimensions. Fullscreen creates the captured signed number of windows at screen dimensions; subsequent windows parent to the first handle. The array at application `+8` is populated in order, and final primary `+4` is reloaded from its first element. Zero/negative count clears primary without clearing old array bytes. The ordinary path either uses the requested dimensions directly or applies `AdjustWindowRectEx` with the original styles, then reloads adjusted dimensions and live caller positions. A nonnull primary invokes `ShowWindow`; that service's return is ignored.

`configureRendererWindows(application,count,windowed,runtime)` skips work unless application byte `+1c` is exactly one. It obtains the stock brush, registers the class, and forwards live settings and original caller arguments. Only the fullscreen temporary's low byte is written before its full DWORD is forwarded, preserving retained high bytes.

`tools/verify-renderer-window-construction-instructions.mjs` passes **4,500 calls, 377 reached instructions and 662,409 steps** over 900 fixture worlds. It compares all mapped bytes at and above `10000h`, defined AL returns, ordered CRT/Win32 requests, exact child ESPs for the window services, and FS restoration. It includes persistent mode switches, class reuse/registration failure, low-word ATOM failures, null window handles, zero count, border adjustment, live instance mutation and 103 actual lazy settings constructions. Six focused tests cover the main recovered rules.

Win32 class/window/GDI/handle operations remain explicit services; these comparisons do not create real windows or invoke an original process. The registered game callback `50d640` now has a separate [actual callback/key-handler proof](renderer-window-messages.md), including persistent constructor→message sequences and an explicit populated-audio gap. The readiness/setup-dialog graph, full device startup `510080`, material/shader initialization and renderer teardown remain separate work.
