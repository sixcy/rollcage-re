# Renderer target registration

`src/renderer-target-registration.mjs` reconstructs actual stock-name constructors `402e80/402ec0`, target registration `517d70` and vector insertion `518060` with actual growth/allocation/fill helpers `518220/518260/518290`. StockScene is an inline ten-byte string; StockRenderTarget is seventeen bytes and reaches heap growth. Original bytes come from REA13048.

Registration compares a nonnull stock key with each target's name at+14h. A match inserts the new pointer BEFORE that target. It neither replaces nor destroys the old object. A missing/null key appends through existing actual `40ebc0`. End is reread after unsuccessful comparisons. Full vector insertion uses the native one-and-a-half capacity policy and copies the new input before moving old ranges; spare-capacity insertion captures aliased input before shifting. Output iterators are rebased after reallocation, including aliases to the vector's input elements.

The APIs are `constructRendererStockName(output,isTarget,runtime)`, `registerRendererTarget(owner,target,key,unused,runtime)` and `insertRendererTargetPointer(vector,outIterator,position,unused,input,runtime)`, all using raw mapped memory/native entry ESP. Allocation/deletion uses genuine CRT `services.libraryCall`; SSO storage uses the existing actual string adapter's allocation/free handlers. Native capacity/length errors remain explicit errors rather than silent truncation.

Evidence13019/13021/13023/13026/13028/13030/13032 supplies exact assembly. `verify-renderer-target-registration-instructions.mjs` passes2,000fixtures/calls,579 reached instructions,262,249steps. It compares all mapped bytes>=10000h and ordered allocator operations for empty/populated/full/spare vectors, interior/end insertion, aliased input and named/null-key registration. Four focused tests cover alias preservation, rebased iterators, stock-name ownership and duplicate insertion. The native `404020` constructor and full viewport startup use these defaults; their ordinary player/mirror names usually append because they differ from StockRenderTarget.
