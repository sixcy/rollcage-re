# Connected vehicle audio and feedback comparison

`tools/verify-vehicle-audio-connected-instructions.mjs` executes the complete recovered `485300` vehicle audio parent and its actual JavaScript defaults against the union of their retained x86 instructions. It includes the four `484cb0/484d10/484d30/484d90` sound wrappers, `484bb0` emitter, `40ea40` dispatcher, `40db20` channel selection, `40d6d0` position update, `40e5e0` playback/reverb setup, `405e30` name-copy adapter, `40ce20` descriptor initialization and `407380/4074e0/407570/407670` feedback parents. No game audio/feedback decision is replaced by a mutation handler.

The fixtures explicitly supply caller-owned body/session/race/audio records, material and sector records, a populated 64-entry sound bank, allocated round-robin channels, source objects, device-manager interfaces and standard-container storage. Original audio tables, horn sequences and float constants are initialized from retained bytes. Three persistent updates per fixture exercise cache creation, reuse and removal, collision cooldown, horn start/release, speed/gear smoothing, source replacement, reverb installation and haptic descriptor generation. Device callbacks can replace the live race-record body/device fields; source callbacks can replace channel sources and collision inputs. Stop callbacks mutate cached handles before their subsequent native reload.

After each update, the checker compares complete service arguments and order plus body, session, race-record, audio/horn, sound-bank, channel, effect and map memory. Haptic descriptor comparison uses all 20 bytes. Reverb comparison includes the NUL-terminated name and all 52 parameter bytes; unused bytes after the name terminator are stack residue and carry no name semantics. The source uses an explicit caller-provided reverb scratch buffer.

Library boundaries are libaudio source virtual methods, imported device virtual methods, standard C++ map lookup/slot/header/clear/destroy/erase, operator delete, imported scalar `cosf`/`sinf`, compiler cookies and valid-domain CRT bounded string copying. The actual `405e30` adapter is retained in evidence773/774; it guards a null name, sets byte23 to zero and invokes imported `strncpy_s` with destination size24 and limit23. The standard map service preserves native map/header/node/cell addresses and callback-visible ordering. Library internals, malformed string errors, vendor trig implementation, audio-device output and physical feedback are not reconstructed here.

## Validation

`node tools/verify-vehicle-audio-connected-instructions.mjs` passes **1,200 fixtures × 3 updates = 3,600 parent calls**, **1,965 unique retained instructions** and **6,217,399 interpreted steps**. It records **130,997 source virtual calls**, **771 reverb installations**, **1,854 haptic creates**, **3,136 haptic updates**, **377 haptic stops** and **23,211 compiler-cookie checks**. All watched parent/wrapper/helper entries execute, including 85 horn-stop wrapper calls. Exact per-entry counts and evidence IDs are retained in `analysis/vehicle-audio-connected-instruction-check.json`.

`node --test tests/vehicle-audio-connected.test.mjs` passes three focused checks: a smaller connected instruction comparison, actual populated horn release, and haptic create/update/stop with a mutated handle reloaded between stop services. The sound-wrapper and haptic standalone comparisons separately cover signed widths, float32 arithmetic, missing devices and cache aliases; see [vehicle-sound-controls-and-haptics.md](vehicle-sound-controls-and-haptics.md).

This proves agreement with interpreted shipped instructions over explicit synthetic runtime inputs. The fixtures use preallocated channels and do not establish the sound-bank/device/session constructors, allocation failure behavior, original-process execution, audible results or a playable game. Instruction totals overlap the parent and helper reports and must not be added as unique recovered coverage.
