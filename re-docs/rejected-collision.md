# Rejected static contact completion

`completeRejectedCollisionBody(body, handlers, timeOptions)` in `src/body-advancement.mjs` reconstructs `0x47cc20`, invoked by rejected static-contact response. This routine completes frame advancement and writes collision state32. It does not destroy or remove the object. Earlier callback names suggesting removal described an unresolved boundary; the retained function body now resolves that meaning.

For every type except4, it sets `frameTimeQ16` to65536 and `collisionState128` to32 without advancing pose, changing spatial registration or adding attachments. Type4 calls the shared `0x479d20` pose routine with the wrapped signed remaining interval `65536-frameTimeQ16`, even when the interval is zero or negative. It updates the clock, refreshes spatial registration if any position high byte changed, then writes state32. Spatial hooks therefore observe the completed pose and clock with the previous collision state still present. Flag `0x8000` does not bypass this type4 path. Type4 is ineligible for the shared routine's special time scaling.

The shared pose callee also appends the body to the attachment queue when its attachment count is nonzero. This occurs even for zero remaining time. The first complete native comparison exposed that side effect, and the implementation now preserves it. Native `0x479eab..0x479ec2` tests the attachment count and performs the append inside `0x479d20`; the caller has no separate attachment instruction. Existing queue entries remain unchanged.

`node tools/verify-rejected-collision-instructions.mjs` passes4,000 fixtures over582 retained instructions and780,187 interpreted steps. All numeric callees are interpreted: pose advancement, both quaternion normalizers, matrix conversion, lookup root and fixed division. Only spatial removal/insertion are explicit nonmutating boundary mocks. It compares all384 body bytes, all384 body bytes observed at each ordered spatial callback, the attachment queue count and64 retained queue bytes.

Fixtures include2,000 type4 and2,000 other-type cases,1,177 overshot clocks,1,193 negative clocks,1,334 `0x8000` flags, signed wrapping coordinates and boundary crossings. They produce1,744 spatial refreshes and667 attachment appends. Six focused tests separately cover other-type retention, negative remaining time, callback order/state, completed-clock attachments, the flag/time-scaling behavior and quaternion integration. `verifyRejectedCollisionBody` is exported for checks against additional declared inputs.

Evidence is retained in `analysis/native-simulation/results/070-body-removal.json` and `071-body-removal-assembly.json`; those filenames preserve their original request labels.
