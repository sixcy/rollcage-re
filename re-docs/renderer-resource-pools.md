# Renderer resource-pool ownership

`src/renderer-resource-pools.mjs` reconstructs the three pools reached by device constructor 50f510: vertex descriptors (514600/514310), texture descriptors (5131b0/513640) and integer IDs (513330/513940). All three constructors initialize 128 entries. Vertex resize 514310 has a fixed 128-entry target; its apparent pushed ECX parameter is unused. Native IDs remain numeric, without guessed resource semantics beyond retained class names.

Actual children include 5141f0/514290 100-byte vertex descriptor construction, 514a70/50ee50/513dd0 460h-byte texture descriptor construction and 513e40 integer initialization to FFFFFFFFh. Texture vtables and exact packed field widths are retained. Constructor padding remains allocator-owned bytes rather than blanket zeroing.

Each pool owns a rebuilt live pointer table, vector of allocated chunks, allocated-index vector and circular free-index deque. Growth allocates one new chunk and appends its indices. Shrink retains whole chunks until their cumulative capacity covers the request, discards later chunks and out-of-range allocated/free indices, and rebuilds the pointer table. Thus shrinking 160 entries to 3 can retain the original 128-entry chunk. Deque map growth, four-word blocks, temporary deque construction and reverse block deletion are real algorithms; only genuine CRT allocation/delete/copy services remain external.

Runtime uses caller-owned raw memory, native `scratchBase` and `services.libraryCall(name,args,runtime)` for operatorNew/operatorNewArray/operatorDelete/operatorDeleteArray. Array allocation overflow retains the native FFFFFFFFh size request. This package does not allocate from the host heap itself. Native private deque addresses are preserved where their sentinel backlinks are visible even after storage deletion.

`analysis/renderer-resource-pools-instruction-check.json` passes 90 persistent scenarios and 450 actual calls: 1,249 reached instructions, 4,880,550 interpreted steps. Each scenario executes the real constructor then four resize operations. It includes 4,800 actual texture objects, 3,840 vertex descriptors, 53,760 actual free-index appends and 1,080 deque growth calls. All mapped bytes at or above 10000h, ordered CRT requests and balanced explicit synthetic FS:[0] match. Four focused tests cover descriptor padding/flags, real128-ID construction, whole-chunk shrink, release-to-zero and a reduced native corpus.

The corpus begins with real constructors and empty allocated-index vectors. Actual texture acquisition is now covered separately in [renderer-texture-ownership.md](renderer-texture-ownership.md); release/upload consumers remain open. This pool corpus does not validate arbitrary malformed pool metadata, allocation-failure unwinding, every allocated-index compaction input or enormous allocation counts. This closes the normal resource-storage dependencies needed for the device constructor, not renderer startup, resource loading or graphics-device execution. Installed files remain read-only.
