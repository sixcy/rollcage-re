# Expert Racing test with adjustable AI count

The standalone Track Viewer enables the **super experimental Racing test** on all verified Rollcage LOW/HIGH tracks except **LEV16 and LEV17**, excluded at the user's request because they lack racing paths. The AI cars slider selects **one to six cars on Expert**, defaulting to **three**, using the first selected number of native vehicle types0 through5, original archive models and distinct authored grid slots. All cars share the collision world and run their own recovered AI, controls, physics and checkpoint state. Start/Pause/Resume, Step frame, Test recovery, Reset race, a Car to follow selector, free cameras, speed and continuous lap/best-time readouts run locally from the user's archive. Driving, collisions and lap timing may be inaccurate. Stage II, Firebugs and the excluded levels retain static preview/export behavior. No game assets are embedded or uploaded.

The visible physics HUD shows the selected car's speed, recovery count and four actual wheel-contact flags, alongside the logical tick and latest shared-world collision/terrain/model hit counts. Its Telemetry toggle changes visibility only. **Step frame** advances the complete world exactly one nominal 1/30-second tick and stays paused. **Test recovery** queues the selected car's state32 immediately before the real post-frame recovery routine; while paused or ready it also advances one tick, and while running it waits for the next tick. The routine computes the route, obstruction checks and resulting pose; the control does not set a display pose or reset the session. Repeated pending requests coalesce. Reset race rebuilds the selected roster and scenery, clearing pending requests and diagnostics. A collapsible Physics progress note distinguishes observed native checks from incomplete timing, weapons and respawn effects.

Expert uses the original selector2: resource008's `PC_MENU_OPTIONS_SETUP_DIFFICULTY` orders Easy/Hard/Expert, and native43da60 clamps session+585 to0..2. The original frontend separately gates the harder choices by unlock flags; this research viewer explicitly selects a difficulty and does not emulate frontend progression. Setting session+585 before410060 publishes2 at5ea4d8;41ebb0 and the other recovered policy routines apply their native Expert changes. No added acceleration, grip or speed multipliers implement difficulty. Session+579 and920f84 are separate AI/game-mode selectors.

This extends the initial LOW/LEV1-only release. The current native-placement/PC24 runtime initializes all 36 allowed variants and runs 600 steps each without exceptions. That short run does not establish completed laps or correct checkpoint behavior on every track; the multi-lap evidence below remains specific to LOW/LEV1. The viewer prominently labels the wider feature super experimental.

The HUD also shows the followed car's **Race position** as `1st / 6`, `2nd / 6`, etc. `snapshot.cars[index].racePosition` exposes the actual one-based participant rank byte at record+1d, maintained by the recovered449640 progression pass. Presentation does not sort cars or estimate their order from distance. Switching the followed car immediately changes the displayed rank. The slider warns that the racing simulation runs in JavaScript and more AI cars can lower FPS. Committing a new count restarts the complete selected roster, scenery and weapons from cached archive inputs without reloading the static track. A valid followed-car selection is retained; reducing below that selection follows the last remaining car. Reset and track/weapon changes keep the chosen count. Unsupported tracks disable the slider. ## Rendering and exclusions

Embedded 40-byte model packets supply original car/wheel UVs and texture pages 26/30/31 through `readDefaultModelMaterials`; these are distinct from placed-object UV-index starts. The native `474490` publication and `46c7c0` consumption establish this path (retained scene result 079, Evidence `ev_29968ccbdad60701a6cf52354fc5e26ce579ec6483c89066df01d694d89cb121`). The independent WebGL renderer applies `S*R*S` to local display geometry and `S*p` to position, with `S=diag(1,-1,-1)`.

The chase camera is a viewer feature with world-up orientation and smoothed heading. Its translation uses the same interpolated pose as the drawn selected car. Free camera movement and terrain/object visibility filters do not change simulation. Car buffers/textures are separate from track/export assets and released on track replacement or context loss. Runtime errors stop practice with an error message while preserving the static viewer; reloading the track retries initialization.

The Car to follow selector offers all six existing cars while paused or running. It changes camera focus, speed/lap/contact readouts and the test recovery target without changing AI state, race scheduling or the roster. Reset race keeps the selected focus; loading a different track returns focus to car1. Disabling follow retains free camera movement while the selected car's telemetry remains available.

Rendering interpolates the two most recent completed30Hz snapshots using the controller accumulator; physics still executes only fixed native ticks. Car parts and scripted scenery use linearly interpolated positions and quaternion short-arc rotations, retaining positive matrix scales. The displayed world runs one physics tick behind the latest completed state to avoid predicting future collisions. The HUD retains current integer physics values. Pause, manual stepping and reset expose the exact latest completed pose; a recovery-count change snaps the affected car immediately instead of interpolating a teleport. Visibility changes also snap. No interpolated value is written into game memory. Matrix-only wheel interpolation retains the visual aliasing limit when a wheel turns more than half a revolution per tick; unwrapped native spin would be needed to distinguish the full rotation direction. This presentation change is not a reconstruction of the original game's render scheduler.

Native class-one/two object breaks, general type-four shape damage, queued/linked model destruction, attachment release, deferred effects and physical world fragments now execute using the actual constructors and shared state. Completed breaks remove object groups from the Racing test display; reset restores them. During active collapse, the viewer retains the authored mesh until completion rather than drawing its changing native vertex/rotation data. Scripted modeled scenery uses native poses, collision callbacks and retirement/shrink state in the viewer; type20 UV changes remain outside its rendering. World fragments, particles and debris are simulated but not drawn. Optional weapons now render original pickup/projectile meshes; audio, trails, several weapon effects and original camera/render submission remain outside this release. Unsupported special vehicle events throw instead of receiving invented gameplay answers. Attachment transforms use exact x87 PC24 nearest-even arithmetic, matching the measured native race context; the remaining numerical operations still need context auditing. Explicit session defaults and the browser service adapter remain declared inputs. See [interaction contracts and evidence](physics-interactions.md#live-destruction-integration) and [scripted-world reconstruction](scripted-world-runtime.md).

`tools/build-solo-runtime-constants.mjs` packages only 17 shared numeric literal spans from retained, target-hash-checked `read_bytes` evidence. Module-owned constructors install their own existing AI/angle/model/profile/particle tables. No interpreter, synthetic fixture builder, original executable or complete executable image enters the browser bundle.
