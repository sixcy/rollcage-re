# Single-car Racing test

The standalone Track Viewer enables the **super experimental Racing test** on all verified Rollcage LOW/HIGH tracks except **LEV16 and LEV17**, excluded at the user's request because they lack racing paths. Start/Pause/Resume, Reset car, Follow car, free cameras, speed and continuous lap/best-time readouts run locally from the user's archive. Driving, collisions and lap timing may be inaccurate. Stage II, Firebugs and the excluded levels retain static preview/export behavior. No game assets are embedded or uploaded.

This extends the initial LOW/LEV1-only release. A headless smoke check initialized all 40 Rollcage variants and ran 600 steps each without exceptions. That short run does not establish completed laps or correct checkpoint behavior on every track; the multi-lap evidence below remains specific to LOW/LEV1. The viewer prominently labels the wider feature super experimental.

## Runtime boundary

`src/solo-session.mjs` exposes `createSession(data, textureData)`, returning `step()`, `reset()`, `dispose()`, `assets` and an immutable `snapshot`. Reset constructs the same seeded state from preserved source copies. A session owns a bounded 64 MiB memory buffer, an aligned allocation service, explicit session/configuration roots, particle/debris storage, and one participant. Allocations stay beyond native constant/global spans. Installed inputs remain unchanged.

The adapter uses the checked `44c46a..44c71d` relocation section and the `44c2b0` runtime-pack publications for routes, checkpoints, spawn/model lookups, spatial maps, normals and material tables. Ordinary scenery maps decoded collision instances to raw object/configuration fields and native model/shape addresses. It publishes the obstacle registry through `appendLoadedWorldObstacle`, allowing actual `4123a0` obstacle construction. This bounded adapter is **not** execution of the complete `47ea40/44c2b0` session/renderer startup graph.

Actual `41dbb0` constructs vehicle type 0 at authored starting slot 0, selecting primary model 39 and wheel model 38 from LEV1. Actual `410060` initializes autonomous state, profiles, ownership, route flags and private RNG. A ready-pose bridge refreshes the constructor's changed quaternion into its rotation/derivative caches and runs `41d2b0`, so the car and four wheels have valid initial display poses.

Each step follows the relevant `450e50` order: previous controls; `410220` AI dispatch/planning/recovery; `431750` route speed/steering; `42a6e0/42a9a0` input conversion; `449640` route/progress/ranking; `420500` handling; complete connected `4749e0` vehicle physics; `47ccc0` post-frame rejection/query/respawn; `443d90/48d680` speed/surface drive; `41d2b0` wheel presentation; debris/particle retirement. AI, body, wheels, collision pools, spatial buckets and checkpoint views share the same memory. Terrain and ordinary model contacts are computed; there is no spline, substitute steering/acceleration model, or forced trajectory correction. Genuine native recovery remains enabled.

Native time-trial session mode 1 retains lap 1 instead of finishing a finite race. The viewer counts genuine checkpoint-zero completion calls and times them separately. **Pacing is an explicit viewer choice: 60 recovered ticks per second.** Native clock `90a548` still advances one count per step; its existing `(clock<<11)/3` timer fields are not presented as wall time. The viewer shows `ticks/60` elapsed seconds. Original process clock scheduling, speed/time calibration and original lap-time equivalence are unproved. A hidden tab pauses; long render delays cap catch-up at eight steps without changing numerical dt.

## Rendering and exclusions

Embedded 40-byte model packets supply original car/wheel UVs and texture pages 26/30/31 through `readDefaultModelMaterials`; these are distinct from placed-object UV-index starts. The native `474490` publication and `46c7c0` consumption establish this path (retained scene result 079, Evidence `ev_29968ccbdad60701a6cf52354fc5e26ce579ec6483c89066df01d694d89cb121`). The independent WebGL renderer applies `S*R*S` to local display geometry and `S*p` to position, with `S=diag(1,-1,-1)`.

The chase camera is a viewer feature with world-up orientation and smoothed position/heading. Free camera movement and terrain/object visibility filters do not change simulation. Car buffers/textures are separate from track/export assets and released on track replacement or context loss. Runtime errors stop practice with an error message while preserving the static viewer; reset retries initialization.

Scenery remains static. Model-contact destruction callbacks deliberately suppress break/damage actions; their collision geometry is active. Weapons, pickups, opponents, audio, original camera/render submission, visual particle drawing, world fragments and dynamic scenery are outside this release. Reached wheel-effect and respawn-particle numeric/lifetime routines run using actual allocated pools, without drawing them. Unsupported special vehicle events throw instead of receiving invented gameplay answers. Nearest-even rounding, explicit session defaults and the browser service adapter remain declared inputs.

`tools/build-solo-runtime-constants.mjs` packages only 17 shared numeric literal spans from retained, target-hash-checked `read_bytes` evidence. Module-owned constructors install their own existing AI/angle/model/profile/particle tables. No interpreter, synthetic fixture builder, original executable or complete executable image enters the browser bundle.
