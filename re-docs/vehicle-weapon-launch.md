# Participant weapon activation

`launchVehicleWeapon(record, slotIndex, localMode, unusedContext, packet, runtime)` in `src/vehicle-weapon-launch.mjs` reconstructs `47be20`. ECX is the participant record, EDX is the selected slot, and stack arguments are localMode/context/packet. **The parent never reads its middle context argument.** Actual child activations receive the selected slot as their transport context. This corrects the earlier tentative interpretation of the outer coordinator's carried ECX. The function returns numeric EAX; native final ECX is always the cookie global after the compiler check.

Every switch branch now defaults to actual source: ground/homing/satellite launch, terrain wave, race launch impulse, time effect, contact-color effect and wormhole. Successful ordinary projectile/contact/launch slots become `FF`; wave/wormhole and a newly owned time effect retain bit40. The time-effect return2 preemption path reports success but consumes the slot. The captured slot pointer, captured original body for the launch button mask, live participant-body reloads, local/network gates, signed slot bytes and inline wormhole feedback are retained. Invalid signed codes and the `FF` sentinel return failure.

The same module includes actual `41e4a0` held recovery: a signed speed at or below `200000h`, any of four wheel contact bits, an empty request and permitted session mode are required. This is distinct from the later recovery/respawn algorithm.
