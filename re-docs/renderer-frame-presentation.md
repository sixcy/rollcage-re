# Renderer frame presentation and timing

`src/renderer-frame-presentation.mjs` reconstructs actual `5290c0` through the already recovered stopwatch producer/measurement `4a4bf0/4a49e0/4a4ad0`, WindowsApplication getter `402aa0`, the real `402da0` command-16 branch, and Direct3D Present. Native evidence: 13246/13247 and 13369–13374, plus original command table 13432. The command's byte-table entry is 7, selecting the simple AL-success branch `402e16`; other Application commands have different algorithms and are not replaced by that constant gate.

`presentRendererFrame(manager,runtime)` increments the wrapping DWORD frame counter `+554`. The stopwatch produces an unsigned 64-bit nanosecond result, which the caller deliberately reinterprets as signed for the CRT millisecond division. Only the quotient's low DWORD becomes global timestamp `714c4c`. Elapsed time subtracts the old DWORD with wrap, and manager `+558` keeps the unsigned maximum. Negative/wrapped timestamps can therefore produce large elapsed intervals; the source retains that behavior.

The original caller leaves the stopwatch output pointer on its stack while obtaining the singleton, then calls its measurement routine at the same child entry. The reference preserves those actual ESPs and known saved caller registers. After timing, Application is resolved through the actual singleton/RTTI, the original command-16 target is checked, and Present rereads the live manager device. Its HRESULT is ignored and native AL success is retained.

`tools/verify-renderer-frame-presentation-instructions.mjs` passes **8,100 calls, 441 reached instructions and 1,569,575 steps** in 900 fixture worlds. It compares all mapped bytes at and above `10000h`, defined returns, ordered CRT/Win32/COM requests with native child ESPs, and restored FS state. The proof includes 4,500 actual present/timing/command chains, 258 lazy stopwatch constructions, and 3,600 actual clear/viewport calls in four persistent clear→present frames. Fixtures cover signed quotient selection, unsigned maximum and frame/timestamp wrap, frequency/counter service failures with declared outputs, clock-root replacement, and RTTI-side device mutation. Four focused tests preserve those main rules.

Standard CRT 64-bit arithmetic and RTTI, OS clocks/critical sections, and Direct3D are explicit services. All reached game code in this bounded graph runs as retained instructions, without game mocks or original-process/device execution. This closes presentation's reached command-16 path, not the full Application dispatcher or device startup `510080`. Material/shader initialization, readiness/dialog/settings orchestration and renderer shutdown remain separate work.
