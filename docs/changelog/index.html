Track Viewer changelog

2026-10-25 · Native terrain checks and editor polish

Available now

• The updated viewer includes terrain heights and surface painting, with projects and game-file export on all 20 levels.

• Workspace tabs and editor actions remain accessible while scrolling; export help is collapsible.

• Project loading keeps the selected tool active. Surface thumbnails use original LOW textures even while editing HIGH.

Validation and limits

• Original Rollcage Redux loaded edited LEV16 and LEV17 resources in both LOW and HIGH, confirmed by native loader names and matching in-memory terrain bytes.

• Separate LEV1 LOW/HIGH captures recorded actual wheel contact with an edited cell. The native point lies on the exported plane and the returned normal matches.

• Browser checks cover all 40 variants, terrain and surface clicks, undo/redo, cancellation, project reload and independently checked game-file ZIP contents.

• LEV16/17 AI Racing test remains disabled. Loading acceptance does not establish usable paths or AI races there.

• These are selected native cases. Full-track contacts, continuous races, all grip behavior and native scenery export remain unverified.

2026-10-25 · Surface painting and terrain projects

Available now

• The Surfaces tool offers searchable thumbnails and an eyedropper for existing static surface presets.

• Painting copies a full native texture/UV/category/grip preset without changing shared descriptors or inventing collision on decorative cells.

• Version-3 projects save sparse height and surface edits together with pickups and scenery; version-1/2 projects remain readable.

• Test changes starts a race from the compiled terrain on racing levels; LEV16/17 offer Preview changes.

Validation and limits

• Headless Edge checks real brush and paint clicks, undo/redo, cancellation, project round-trip and an edited race restart.

• Sources remain read-only. Game export produces a new archive pair for a separate installation.

• New textures, Blender imports, new sectors and route editing remain future work.

2026-10-25 · Terrain height tools

Available now

• Track editor has Raise, Lower, Smooth, Flatten and Set height brushes.

• Brushes follow connected grids and matched sector seams, with a live wire preview, cancellation and undo/redo.

• Height edits update LOW/HIGH together and regenerate touched collision planes and spatial coverage.

• Animated sectors and point-animated regions are visibly locked; unsupported/capacity-breaking edits are rejected before changing the project.

Validation and limits

• All 20 LOW/HIGH source pairs pass no-edit byte identity and representative edited-resource checks.

• Edited source simulations run on the 18 racing levels. LEV16/17 use static preview.

• Pickups, scenery, starting grids and routes retain their saved positions; substantial terrain changes may require manual adjustment.

• These checks are not original-game terrain-export acceptance. Native acceptance is a separate delivery.

2026-10-25 · Workspaces and all-level editing

Available now

• Explore, Racing test and Track editor workspaces replace the long mixed sidebar.

• Loading controls collapse after a source is loaded; camera controls and update history remain accessible.

• LEV16 and LEV17 support pickups, compatible model libraries, project saving and export.

• These two levels offer Preview changes; their AI Racing test remains unavailable.

Validation and limits

• Editor support is separate from AI racing support. Existing object/resource limits still apply.

• Source/browser validation and native export acceptance are reported separately; this change does not claim new original-process acceptance.

2026-10-25 · Editor baseline and update history

Available now

• The viewer has a local What’s new panel and a complete static changelog.

• Current documentation separates working editor features, experimental exports and original-game verification.

• Editor checks have their own command; broader inherited failures remain recorded separately.

Validation and limits

• Changelog content is embedded at build time; opening the viewer requires no network requests.
